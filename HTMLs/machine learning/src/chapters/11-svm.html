Support vector machines

If many lines separate two classes, pick the one with the widest safety margin. Then bend space so that a straight line can separate almost anything.

The widest street

When two classes can be separated by a line, there are infinitely many lines that do it. Logistic regression picks one based on probabilities. A support vector machine picks the line that sits in the middle of the widest possible "street" between the classes. A wide margin means small nudges to the data will not flip predictions, which tends to generalize well.

The remarkable part: the street is defined entirely by the few points touching its edges, the support vectors. Every other point could be deleted or moved (without crossing the street) and the answer would not change at all.

Soft margins and the C parameter

Real data overlaps, so the SVM is allowed to let points into the street or even across it, at a price. It minimizes the hinge loss plus a penalty on weight size:

λ||w||² + 1n Σi max(0, 1 − yi(w · xi + b))Labels are ±1. A point well on the correct side contributes zero, which is why only support vectors matter.

Small ||w|| means a wide margin (the width is 2 / ||w||). In libraries the trade-off is set by C, which behaves like 1/λ: big C, low tolerance for violations, higher risk of overfitting.

The kernel trick

What if no straight line can separate the classes? Look at the one-dimensional data below: one class sits in the middle, the other on both sides. No single threshold splits them. But add a feature, x², and the data lifts onto a parabola where a flat line separates it perfectly.

Computing huge feature expansions explicitly would be expensive. The trick is that the SVM's math only ever needs dot products between examples, and for many useful feature maps the dot product in the big space can be computed directly from the original vectors. That shortcut function is a kernel:

  • Polynomial kernel (x · z + 1)d: implicit polynomial features of degree d.
  • RBF (Gaussian) kernel exp(−γ ||x − z||²): similarity that decays with distance. It corresponds to an infinite-dimensional feature space and can carve out almost any boundary. γ sets how local each point's influence is; large γ overfits.

SVMs were the state of the art in the 2000s. Today they remain strong for small to medium datasets, and linear SVMs are still excellent for high-dimensional sparse data such as text classification with word counts. Kernel SVMs scale poorly past roughly 100,000 examples, and gradient-boosted trees or neural networks usually take over. Always scale features first: the margin is a distance.

In code

from sklearn.svm import SVC, LinearSVC
from sklearn.preprocessing import StandardScaler
from sklearn.pipeline import make_pipeline
from sklearn.model_selection import GridSearchCV

svm = make_pipeline(StandardScaler(), SVC(kernel="rbf"))
grid = GridSearchCV(svm, {"svc__C": [0.1, 1, 10, 100],
                          "svc__gamma": ["scale", 0.01, 0.1, 1]}, cv=5)
grid.fit(X_train, y_train)
print(grid.best_params_, grid.score(X_test, y_test))

text_clf = LinearSVC(C=0.5)          # fast linear SVM for sparse text features

You delete a training point that is not a support vector and retrain the SVM. What happens to the boundary?

Only support vectors carry non-zero weight in the solution. Removing any other point leaves the optimal boundary unchanged.

An RBF-kernel SVM gets 100% training accuracy and poor test accuracy. Which change should help?

Large C and large gamma both increase flexibility. Lowering them yields a smoother boundary and less overfitting.

What does the kernel trick let an SVM do?

Kernels compute dot products in the expanded space directly from the original vectors, giving non-linear boundaries at a fraction of the cost.
