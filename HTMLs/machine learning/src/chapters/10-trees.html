Decision trees and ensembles

A tree asks a sequence of yes/no questions. One tree is readable but fragile. Hundreds of trees combined are among the most powerful tools for tabular data that exist.

A game of twenty questions

A decision tree predicts by walking from the root to a leaf, answering one question per node: "Is income above 52k? Is age below 30?" Each leaf holds a prediction: the majority class of the training examples that ended up there (or their average value, for regression). You can print a tree and hand it to a colleague, and they can follow it by hand.

How a tree picks its questions

Training is greedy. At each node, try every feature and every threshold, and pick the split that makes the two child groups as pure as possible. Purity is measured by Gini impurity (or entropy):

Gini = 1 − Σk pk²0 for a group of one class only; 0.5 for a 50/50 mix of two classes.

Then repeat inside each child, recursively, until the groups are pure or a stopping rule kicks in: a maximum depth, or a minimum number of samples per leaf. Regression trees use the same procedure with variance instead of Gini.

Ensembles: the wisdom of crowds

If you average many models whose errors are at least partly independent, the errors cancel and the average is better than any individual. The two great ways to build tree ensembles are bagging and boosting.

Bagging and random forests

Bagging (bootstrap aggregating) trains each tree on a random sample of the data drawn with replacement, then averages their votes. A random forest adds one more twist: at each split, a tree may only consider a random subset of features. That forces the trees to be different from one another, which makes the averaging far more effective. Random forests are hard to break, need little tuning, and are a superb first model for almost any table of data.

Bonus: each tree skips about a third of the examples in its bootstrap sample. Predicting those out-of-bag examples gives a free validation score.

Boosting

Boosting builds trees in sequence instead of in parallel. Each new tree is trained to fix the mistakes of all the trees before it. In gradient boosting, each tree is fitted to the residuals (the remaining errors), and its prediction is added in with a small weight ν, the learning rate:

Fm(x) = Fm−1(x) + ν · treem(x)

For squared error, the residual y − F(x) is exactly the negative gradient of the loss with respect to the prediction. So each tree takes one gradient descent step, not in parameter space but in function space. Swap in another loss's gradient and the same machinery handles classification, ranking or any differentiable objective.

XGBoost, LightGBM and CatBoost are the industrial-strength gradient boosting libraries. On tabular data they routinely beat deep learning and win a large share of Kaggle competitions. Key hyperparameters: number of trees, learning rate (smaller is better but slower), max depth (3 to 8 is typical), row and column subsampling, and early stopping on a validation set to pick the number of trees automatically.

Which features matter?

  • Impurity importance (the built-in feature_importances_): fast, but biased toward features with many unique values.
  • Permutation importance: shuffle one feature in the validation set and measure how much the score drops. Model-agnostic and more trustworthy.
  • SHAP values: split each individual prediction into per-feature contributions. The standard for explaining tree ensembles to stakeholders.

print("out-of-bag accuracy:", rf.oob_score_)

What makes a random forest's trees different from each other?

Randomness in both rows (bootstrap) and columns (feature subsets) decorrelates the trees, which is what makes averaging them powerful.

In gradient boosting, what is each new tree trained to predict?

Each tree fits what the ensemble still gets wrong (the negative gradient of the loss), then gets added with a small learning rate.

You have a spreadsheet-style dataset with 50,000 rows and 40 mixed features. What is a strong first model?

For tabular data, boosted trees are usually the strongest out-of-the-box option, and random forests the most forgiving baseline.
