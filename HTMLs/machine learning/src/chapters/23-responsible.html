Responsible machine learning

Models make decisions about loans, jobs, medical care and what billions of people see. Getting the math right is necessary, not sufficient.

This is not a soft topic bolted onto the technical ones. Bias, privacy failures and unexplainable decisions are engineering defects with legal, financial and human consequences, and regulation such as the EU AI Act now requires many teams to document and test for them. You will be expected to handle these issues at work.

Where bias comes from

  • Historical bias: the data faithfully records an unfair past. A hiring model trained on past hires learns past preferences.
  • Representation bias: some groups are underrepresented, so the model is simply less accurate for them (face recognition error rates that differ by skin tone are a well-documented case).
  • Measurement bias: the label is a flawed proxy. Using "arrests" as a proxy for "crime" bakes in policing patterns; using "healthcare spending" as a proxy for "health need" underestimates need for groups with less access to care.
  • Feedback loops: predictions shape the future data that retrains the model.

Removing a sensitive column (gender, ethnicity) does not remove the bias: zip code, name, school or shopping habits can act as proxies.

Fairness has several definitions

CriterionAsks that
Demographic parityEach group is selected at the same rate.
Equal opportunityTruly qualified people in each group are selected at the same rate (equal true positive rates).
Equalized oddsBoth true positive and false positive rates match across groups.
CalibrationA score of 70% means 70% in every group.

When base rates differ between groups, it is mathematically impossible to satisfy calibration and equalized odds at the same time (except for a perfect model). Choosing a fairness criterion is therefore a value judgment about which errors matter most, to be made with domain experts and affected people, not silently by whoever writes the code.

Explainability

  • Global: which features matter overall (permutation importance, partial dependence plots).
  • Local: why this particular prediction (SHAP values, LIME, counterfactuals like "approved if income were $4,000 higher").
  • By design: when stakes are high, prefer models that are interpretable in the first place.

Explanations are also a debugging tool. A famous example: a model separating wolves from huskies turned out to be detecting snow in the background.

Privacy and security

  • Models can memorize and leak training data, including personal information. Minimize what you collect, anonymize carefully, and control access.
  • Differential privacy adds calibrated noise so that no individual's presence in the data can be inferred. Federated learning trains across devices without centralizing raw data.
  • Adversarial examples (tiny crafted input changes that flip predictions), data poisoning and prompt injection are real attacks. Threat-model ML systems like any other software.
