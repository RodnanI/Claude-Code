Training deep networks

A real neural network, training live in your browser. Then the practical craft: the settings, tricks and warning signs that decide whether a network learns or flails.

Experiments worth running

  1. Depth vs. no depth. Circle data with 0 hidden layers is logistic regression: it fails. Add one hidden layer with 3 or more neurons and it succeeds. Or keep 0 layers and turn on x₁² and x₂²: hand-made features do the same job.
  2. The spiral. Try it with 2 layers of 4: it struggles. Give it 3 or 4 layers of 8, or the sine features, and be patient.
  3. Linear activation. Choose "Linear" with 4 layers on the circle. No amount of depth helps, exactly as chapter 15 predicted.
  4. Learning rate. Set it to 1 with SGD and watch the loss thrash. Set it to 0.001 and watch it crawl.
  5. Overfitting. Noise at 0.8, 4 layers of 8 neurons, and let it run. Training loss keeps falling, test loss turns upward, and the boundary grows islands around individual noisy points. Now add L2 regularization.
  6. Dead ReLUs. Pick ReLU with a high learning rate and watch some neuron squares go blank: they output zero everywhere and have stopped learning.

Initialization

Weights start random, never all zero: identical weights would make every neuron in a layer compute the same thing and receive the same gradient forever (the symmetry problem). The scale matters too. Too large and activations explode or saturate; too small and signals fade to nothing after a few layers. Xavier/Glorot initialization (for tanh) and He initialization (for ReLU) scale the random weights by the number of inputs so that signal strength stays roughly constant through the layers. Frameworks do this by default.

Normalization layers

Batch normalization rescales each layer's outputs to zero mean and unit variance over the mini-batch, then lets the network learn its preferred scale and shift. It makes training faster and far less sensitive to initialization and learning rate. Layer normalization does the same across the features of a single example instead of across the batch, which is what transformers use.

Regularization, deep learning style

  • Weight decay: L2 regularization, usually via the AdamW optimizer.
  • Dropout: during training, randomly switch off a fraction of neurons (say 10 to 50%) at each step. No neuron can rely on any specific other one, which forces redundant, robust features. At test time all neurons are active.
  • Data augmentation: random crops, flips, color jitter, noise. Often the single biggest win for images.
  • Early stopping: keep the checkpoint with the best validation loss.

A practical recipe

  1. Look at the data for longer than feels necessary. Check labels, duplicates, class balance, weird values.
  2. Get a dumb baseline working end to end, including evaluation, before any cleverness.
  3. Overfit one small batch. A correct network must be able to drive loss near zero on 10 examples. If it cannot, you have a bug.
  4. Then scale up and add regularization only when validation loss says you need it.
  5. Change one thing at a time and keep a log of every run (tools like Weights & Biases or MLflow help).
  6. Tune the learning rate first; it matters more than almost anything else.

Deep learning runs on GPUs because it is mostly matrix multiplication done in parallel. Larger batches use the GPU better but may need a larger learning rate. Mixed precision (16-bit floats where safe) roughly doubles speed and halves memory. When a model does not fit, reduce batch size, use gradient accumulation, or use a smaller model. Free notebooks (Google Colab, Kaggle) give you a GPU to learn with.

In code

import torch
from torch import nn

model = nn.Sequential(
    nn.Linear(20, 128), nn.BatchNorm1d(128), nn.ReLU(), nn.Dropout(0.2),
    nn.Linear(128, 64), nn.ReLU(), nn.Dropout(0.2),
    nn.Linear(64, 1))
opt = torch.optim.AdamW(model.parameters(), lr=3e-4, weight_decay=0.01)
loss_fn = nn.BCEWithLogitsLoss()
best, patience = float("inf"), 0

for epoch in range(200):
    model.train()                                  # dropout and batchnorm in training mode
    for xb, yb in train_loader:
        loss = loss_fn(model(xb).squeeze(1), yb)
        opt.zero_grad(); loss.backward(); opt.step()

    model.eval()                                   # dropout off, batchnorm uses running stats
    with torch.no_grad():
        val = sum(loss_fn(model(xb).squeeze(1), yb).item() for xb, yb in val_loader)
    if val < best:
        best, patience = val, 0
        torch.save(model.state_dict(), "best.pt")  # keep the best checkpoint
    else:
        patience += 1
        if patience == 10:                         # early stopping
            break

Why not initialize all weights to zero?

Random initialization breaks symmetry so that neurons can learn different features.

Training loss keeps falling but validation loss has risen for 15 epochs. What should you do?

This is overfitting. Early stopping keeps the best model; dropout, weight decay, augmentation or more data address the cause.

Your network cannot get the loss near zero even on a batch of 10 examples. What does that suggest?

Any reasonable network should memorize 10 examples. Failing to do so points to bugs in data, labels, loss or the training loop.
