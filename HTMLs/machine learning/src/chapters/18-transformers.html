Embeddings, attention and transformers

The architecture behind ChatGPT, Claude, modern translation and much of today's AI. It rests on two ideas: represent meaning as vectors, and let every word decide which other words matter to it.

From words to vectors

Models need numbers. Text is first split into tokens (words or pieces of words), each token gets an ID, and each ID looks up a learned vector called an embedding, typically with hundreds or thousands of dimensions. Training arranges these vectors so that tokens used in similar contexts end up near each other. Nobody tells the model that "king" and "queen" are related; it discovers it because they appear in similar sentences.

Embeddings are one of the most useful tools in applied ML, even without training anything. Embed product descriptions, support tickets or documents with a pretrained model, then use nearest neighbor search for semantic search, recommendations, deduplication, clustering, or retrieval for a chatbot.

The sequence problem

Meaning depends on context: "bank" in "river bank" versus "bank account". Earlier recurrent neural networks (RNNs, and the improved LSTMs) read text one token at a time, carrying a running memory vector. They worked, but information from far back faded, and processing tokens one after another made training slow and hard to parallelize.

Attention

Self-attention lets every token look at every other token at once and decide how much each one matters to it. Each token produces three vectors from its embedding, using three learned weight matrices:

  • a query q: what am I looking for?
  • a key k: what do I contain?
  • a value v: what will I pass along if chosen?

The relevance of token j to token i is the dot product qi · kj. A softmax turns these scores into weights that sum to 1, and token i's new representation is the weighted average of all the values:

Attention(Q, K, V) = softmax( Q KT√d ) VDividing by √d (the vector size) keeps scores in a range where softmax still has useful gradients.

The transformer block

A transformer stacks identical blocks, each with two parts wrapped in residual (skip) connections and layer normalization:

  • Multi-head attention: several attention mechanisms in parallel, each free to track a different kind of relationship (grammar, coreference, topic).
  • Feed-forward network: an MLP applied to each token separately. Much of the model's stored knowledge is thought to live here.
  • Positional information: attention itself ignores word order, so position is injected into the embeddings (sinusoids, learned vectors, or rotary encodings).
  • Residual connections and layer norm: the ResNet trick from chapter 17, which keeps very deep stacks trainable.

Why transformers took over

All tokens are processed in parallel, which suits GPUs perfectly; any token can reach any other in one step, so long-range context is easy; and performance keeps improving predictably as you add data, parameters and compute (the scaling laws). The same block now handles text, images (Vision Transformers), audio, protein sequences and more.

FlavorAttentionExamples and uses
Encoder-onlyEvery token sees every tokenBERT: classification, search embeddings
Decoder-onlyEach token sees only earlier tokens (causal mask)GPT, Claude, Llama: text generation
Encoder-decoderBoth, linked by cross-attentionT5, original translation transformer

Every token attends to every other, so compute grows with the square of the sequence length. Doubling the context quadruples the attention work. Much engineering (efficient attention kernels, caching, sparse and linear attention variants) exists to fight this.

In code

import torch, torch.nn.functional as F

def self_attention(x, Wq, Wk, Wv, causal=False):
    # x: (tokens, d_model); W*: (d_model, d_head)
    Q, K, V = x @ Wq, x @ Wk, x @ Wv
    scores = Q @ K.T / K.shape[-1] ** 0.5           # (tokens, tokens) relevance
    if causal:                                       # decoder: no peeking at the future
        mask = torch.triu(torch.ones_like(scores), diagonal=1).bool()
        scores = scores.masked_fill(mask, float("-inf"))
    weights = F.softmax(scores, dim=-1)              # each row sums to 1
    return weights @ V                               # weighted mix of values

x = torch.randn(11, 64)
out = self_attention(x, *(torch.randn(64, 16) for _ in range(3)), causal=True)
print(out.shape)   # torch.Size([11, 16])

In attention, what determines how much token i attends to token j?

Scores are query-key dot products, normalized with a softmax. Both vectors are computed by learned weight matrices, so the model learns what to look for.

Why do transformers need positional information?

Without positions, "dog bites man" and "man bites dog" would look identical to attention.
