Measuring what matters

A model is only as good as the number you judge it by. Pick the wrong metric and you will optimize the wrong thing with great precision.

Accuracy lies

A fraud dataset has 1 fraudulent transaction per 100. A "model" that always answers "not fraud" scores 99% accuracy and catches nothing. Whenever classes are imbalanced, and in real problems they usually are, accuracy hides failure. You need to look at the kinds of mistakes separately.

The confusion matrix

Every binary prediction lands in one of four boxes:

Predicted positivePredicted negative
Actually positiveTrue positive (TP)
fraud, flagged		False negative (FN)
fraud, missed
Actually negativeFalse positive (FP)
honest, flagged		True negative (TN)
honest, left alone

From these four counts come the metrics you will use daily:

  • Precision = TP / (TP + FP): when the model says positive, how often is it right? Low precision means false alarms.
  • Recall (sensitivity, true positive rate) = TP / (TP + FN): of all real positives, how many did we catch? Low recall means misses.
  • F1 = 2PR / (P + R): the harmonic mean, high only when both are high.
  • False positive rate = FP / (FP + TN): the share of negatives wrongly flagged.

The threshold trade-off

A classifier outputs a score. You choose the threshold above which you call it positive. Move the threshold and you trade one kind of error for the other. There is no free lunch, only a business decision about which mistake costs more.

Favor recall

Cancer screening

Missing a case is far worse than a false alarm followed by a second test. Use a low threshold.

Favor precision

Spam filter

Hiding a real email from your boss is worse than letting some spam through. Use a high threshold.

Explicit costs

Fraud review

Each flag costs analyst time; each miss costs money. Pick the threshold that minimizes total expected cost.

ROC and AUC

The ROC curve plots true positive rate against false positive rate across every threshold. The AUC (area under it) summarizes the model independent of threshold, and has a lovely meaning: the probability that a randomly chosen positive gets a higher score than a randomly chosen negative. 0.5 is coin-flipping, 1.0 is perfect ranking.

When positives are rare, prefer the precision-recall curve and its area (average precision). It exposes exactly the false-alarm flood the ROC curve hides.

Probabilities should mean what they say

If a model says "70% chance" for a thousand cases, about 700 should turn out positive. A model with this property is calibrated. Ranking metrics like AUC ignore calibration entirely, but it matters whenever probabilities feed decisions or pricing. Modern neural networks are often over-confident; techniques like Platt scaling, isotonic regression or temperature scaling fix calibration after training.

Always have a baseline

Before celebrating a score, compute what a trivial approach gets: predict the most common class, predict the mean, predict "same as last week". A model that barely beats its baseline is not worth its complexity. A shocking number of production projects never check.

Validation scores are noisy. If model A scores 0.842 and B scores 0.838 on 500 examples, that gap is well inside the noise. Use cross-validation (look at the spread across folds) or bootstrap confidence intervals before declaring a winner.

In code

from sklearn.metrics import (confusion_matrix, classification_report,
                             roc_auc_score, average_precision_score)

proba = clf.predict_proba(X_test)[:, 1]
pred = (proba >= 0.3).astype(int)          # a custom threshold favoring recall

print(confusion_matrix(y_test, pred))       # [[TN FP] [FN TP]]
print(classification_report(y_test, pred))  # precision, recall, F1 per class
print("ROC AUC:", roc_auc_score(y_test, proba))
print("PR AUC: ", average_precision_score(y_test, proba))

A disease screening model has 99% precision but 20% recall. What does that mean?

High precision: flags are trustworthy. Low recall: 80% of sick patients go undetected. For screening, that is a bad trade.

Lowering the classification threshold will usually:

A lower threshold calls more things positive: you catch more real positives (recall up) and also more false alarms (precision down). AUC is threshold-independent.

A model has ROC AUC of 0.5. What does that indicate?

An AUC of 0.5 means a random positive is as likely to outscore a random negative as the reverse: no ranking ability at all.
