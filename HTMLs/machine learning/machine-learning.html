Almost every method in this guide is the same four-part recipe: data, a model with adjustable numbers, a loss that scores how wrong the model is, and an optimizer that nudges the numbers to make the loss smaller. When a new technique looks intimidating, ask which of the four parts it changes.

What machine learning is

Machine learning is getting a computer to improve at a task by finding patterns in examples, instead of following rules a person wrote by hand.

Start by doing it. The figure below holds a tiny model. Each dot is an example with a known answer: class A or class B. The shaded background is the model's opinion about every other location on the plane. Add a few points and watch that opinion change.

That is the whole trick in miniature. You supplied data with answers, and the program produced behavior you never spelled out. The rest of this guide is about doing that well: with better models, on messier data, while measuring honestly how good the result is.

Rules versus learning

In traditional programming a person writes the rules and the computer applies them. In machine learning you flip it: you provide inputs together with the answers you want, and a training algorithm produces the rules. Those learned rules are called the model.

Why bother? Because for many useful tasks nobody can write the rules. Try writing an explicit rule for "this photo contains a cat" or "this email is a phishing attempt" or "this sentence is sarcastic". Humans do these effortlessly and cannot explain how. We can, however, collect thousands of labeled examples. ML turns examples into working behavior.

AI, ML, deep learning, LLMs

Deep learning dominates images, audio and text. For tabular business data (spreadsheets and database tables) older methods such as gradient-boosted trees still frequently win. A good practitioner knows both worlds.

When not to use ML

  • A simple rule works. If ten lines of if statements solve it reliably, ship those.
  • You have no data and no realistic way to get it. Models are made of data.
  • Every error is unacceptable. ML is statistical: it will be wrong some fraction of the time. Plan for that or do not use it.
  • The world keeps changing faster than you can collect examples. A model only knows the past it was trained on.

The math you actually need

Four ideas carry almost all of machine learning: vectors, matrices, derivatives and probability. You need intuition for each, not a semester of proofs.

Libraries do the arithmetic for you. What they cannot do is tell you why training diverged, why two features should be scaled, or why a 99% accurate test can still be useless. That judgment comes from understanding what the math means. This chapter builds exactly that, with a figure for each idea.

Vectors: data as arrows

A vector is an ordered list of numbers. A house with 120 m², 3 bedrooms and 15 years of age is the vector x = [120, 3, 15]. In ML, every example becomes a vector, and a dataset becomes a cloud of points in a space with one axis per feature. Two features you can draw; a thousand features you cannot, but the geometry works exactly the same.

The most important operation on vectors is the dot product: multiply matching entries and add them up.

a · b = a1b1 + a2b2 + … + anbn = |a| |b| cos θ

The first form is how you compute it. The second tells you what it means: the dot product is large when two vectors point in the same direction, zero when they are perpendicular, and negative when they point apart.

A linear model's prediction is a dot product between a weight vector and a feature vector: ŷ = w · x + b. A neuron in a neural network computes the same thing. Search engines and chatbots compare meanings by taking the cosine between embedding vectors. You will see dot products in nearly every chapter.

Matrices: many dot products at once

A matrix is a grid of numbers. Your whole dataset is a matrix X with one row per example and one column per feature. Multiplying a matrix by a vector computes one dot product per row, so X w gives predictions for every example in one shot. That is why GPUs, which are built for matrix multiplication, made deep learning practical.

There is a second, geometric way to see a matrix: it is a transformation that moves every point in space. A 2×2 matrix tells you where the two basis arrows land, and everything else follows along.

Derivatives: which way is downhill?

Training a model means adjusting parameters to make the loss smaller. To do that you need to know, for each parameter: if I nudge it a little, does the loss go up or down, and how quickly? That rate is the derivative. Geometrically it is the slope of the tangent line.

f′(x) = limh→0 f(x + h) − f(x)h

Models have many parameters, so we take a derivative with respect to each one while holding the others fixed. These are partial derivatives, and stacking them gives the gradient:

∇L = [ ∂L/∂w1, ∂L/∂w2, …, ∂L/∂wn ]The gradient points in the direction of steepest increase. Step the opposite way to decrease the loss.

One more rule and you have everything deep learning needs. The chain rule says that when functions are nested, their rates of change multiply: if y = f(g(x)) then dy/dx = f′(g(x)) · g′(x). A neural network is a long chain of nested functions, and backpropagation is simply the chain rule applied efficiently from the output backward.

Probability: reasoning under uncertainty

Data is noisy and predictions are uncertain, so ML speaks probability. The essentials:

  • Distribution: how likely each value is. The normal (Gaussian) bell curve shows up everywhere because sums of many small effects tend toward it.
  • Mean μ: the center. Variance σ²: the average squared distance from the mean. Standard deviation σ: its square root, in the original units.
  • Conditional probability P(A | B): the probability of A given that B happened. Classifiers output exactly this: P(spam | the words in this email).

Bayes' rule lets you flip a conditional around:

P(A | B) = P(B | A) · P(A)P(B)

It sounds abstract until you try it. A disease affects 1% of people. A test catches 90% of sick people and falsely flags 5% of healthy ones. You test positive. What is the chance you are sick? Most people, including many doctors, guess around 90%. Count it out below.

Data comes first

A mediocre algorithm on good data beats a brilliant algorithm on bad data, nearly every time. Practitioners spend most of their hours here, and for good reason.

Split before you do anything else

The goal is performance on unseen data, so you must hold some data back and never let the model, or yourself, peek at it during development.

  • Training set: the model learns its parameters here.
  • Validation set: you compare models and tune hyperparameters here.
  • Test set: touched once, at the very end, to report expected real-world performance.

When data is scarce, k-fold cross-validation reuses it better: split the training data into k parts, train k times, each time validating on a different part, then average the scores.

  • Time series: never shuffle. Train on the past, validate on the future, or you are predicting yesterday with tomorrow's data.
  • Groups: if one patient has ten scans, all ten go in the same split. Otherwise the model recognizes the patient, not the disease.
  • Imbalanced classes: use a stratified split so each part keeps the same class proportions.

Feature scaling

Many algorithms measure distances or take gradient steps in feature space. If one feature is measured in dollars (tens of thousands) and another in years (tens), the dollar feature silently dominates. The fix is to put features on comparable scales:

  • Standardization: z = (x − μ) / σ. Mean 0, standard deviation 1. The default choice.
  • Min-max scaling: (x − min) / (max − min). Squeezes into 0 to 1. Sensitive to outliers.

Tree-based models (decision trees, random forests, gradient boosting) split one feature at a time and do not care about scale. Distance-based and gradient-based models (k-NN, SVMs, linear models, neural networks) care a lot.

The rest of the cleanup

  • Missing values: fill with the median or most frequent value, and often add a "was missing" 0/1 column, because missingness itself can be informative.
  • Categoricals: one-hot encode low-cardinality columns. For thousands of categories consider target encoding or learned embeddings.
  • Skew: take the log of heavy-tailed values like income or prices so a few giants do not dominate.
  • Outliers: find out whether they are errors (fix or drop) or rare truths (keep, maybe clip).
  • Feature engineering: turn raw data into signals the model can use. A timestamp becomes hour of day and day of week; two amounts become their ratio; a house's year built becomes its age.

Data leakage: the silent killer

Leakage is when information that would not be available at prediction time sneaks into training. It produces spectacular validation scores and a model that fails in production. Classic cases:

  • Preprocessing on all data: fitting the scaler or imputer on the full dataset before splitting lets test statistics shape training. Fit on train only, then apply to the rest.
  • Target leakage: predicting customer churn with a feature like "cancellation_reason", which only exists after they churned.
  • Duplicates across splits: near-identical rows in train and test make memorization look like skill.
  • Future information in time series features, such as a 7-day average centered on the prediction date.

If a result looks too good to be true, suspect leakage first. Ask of every feature: would I actually know this value at the moment I need the prediction?

You standardize features using the mean and standard deviation of the entire dataset, then split into train and test. What is the problem?

The scaler "saw" the test data. The effect is often small, but it is leakage and with other preprocessing (like target encoding) it can be large. Always fit preprocessing on train only.

You are predicting next month's sales. How should you split the data?

With time involved, a random split lets the model learn from the future. A chronological split mimics how the model will actually be used.

Which model is least affected by unscaled features?

Trees split on one feature at a time using thresholds, so multiplying a feature by 1,000 does not change which splits are possible.

Linear regression

The "hello world" of machine learning, and still one of the most used models in industry. Everything you learn here carries straight into neural networks.

The model

We want to predict a number y (a house price) from a feature x (its size). The simplest guess is a straight line:

ŷ = w x + bw is the slope (price per extra square meter), b is the intercept (the baseline). These two numbers are the model's parameters.

With several features the line becomes a flat plane (or hyperplane), but the idea is identical: each feature gets its own weight and the prediction is a weighted sum, which is a dot product.

ŷ = w1x1 + w2x2 + … + wnxn + b = w · x + b

The loss: how wrong is a line?

For each example, the residual is the gap between truth and prediction: yi − ŷi. We need one number summarizing all residuals. The standard choice squares each one and averages them, the mean squared error:

MSE = 1n Σi (yi − ŷi)²

Squaring does useful things: negatives cannot cancel positives, big misses are punished much more than small ones, and the result is a smooth bowl-shaped function of w and b that is easy to minimize. In the figure the squared errors are drawn as literal squares. Training means making their total area as small as possible.

You just did what every training algorithm does: adjust parameters, watch the loss, repeat. The only difference is that computers do it with calculus instead of sliders, and with millions of parameters instead of two.

Solving it exactly

For linear regression with MSE there is a closed-form answer, the normal equation. Put all examples in a matrix X (with a column of ones for the intercept) and targets in y:

θ* = (XTX)−1 XT y

This works well for thousands of features. For millions of rows or features, or for models without a closed form (almost all others), we use the iterative method in the next chapter: gradient descent.

Reading the weights

A weight says how much the prediction changes when its feature increases by one unit, holding all other features fixed. That makes linear models wonderfully interpretable, with caveats:

  • Weights are only comparable if features share a scale. Standardize first if you want to rank feature importance by weight size.
  • If two features are strongly correlated (size in m² and in ft²), their weights become unstable and can take absurd opposite signs. This is multicollinearity.
  • A weight measures association in this dataset, not causation. Houses with pools cost more, but adding a pool does not add the whole difference.

Curves with a linear model

"Linear" refers to the parameters, not the shape. Add features like x², x³ or log x and the same machinery fits curves. This is polynomial regression, and it is also the perfect way to learn about overfitting, which is exactly what chapter 08 does.

Why is the error squared in MSE rather than just summed?

Summing raw residuals lets +10 and -10 cancel to zero. Squaring keeps everything positive and gives a smooth loss that heavily penalizes big misses.

A model has R² = 0 on the test set. What does that mean?

R² compares your error to the error of the constant "predict the mean" baseline. Zero means no improvement over that baseline.

Gradient descent

The engine inside nearly every modern model. Walk downhill on the loss, one small step at a time.

Picture the loss as a landscape. Every possible setting of the parameters is a location, and the height at that location is the loss. Training means finding a low point. The catch: you are standing in thick fog. You cannot see the valley, only feel the slope under your feet. So you do the obvious thing: take a step in the steepest downhill direction, feel again, repeat.

θ ← θ − η ∇L(θ)Parameters move against the gradient. η (the learning rate) sets the step size.

That single line trains linear regression, logistic regression and every neural network from a tiny classifier to the largest language models. What changes is how the gradient is computed (backpropagation, chapter 15) and a few refinements to the step.

The learning rate is the most important knob

Take steps too small and training crawls. Take them too large and you overshoot the valley floor, bounce up the other wall, and can fly off entirely. Try it on the simplest possible loss, L(w) = w².

When a training run's loss explodes to NaN, the first suspect is a learning rate that is too high. When loss decreases painfully slowly, try raising it by 3x to 10x. Sweeping learning rates on a log scale (0.1, 0.03, 0.01, 0.003…) is standard practice.

Two dimensions and better optimizers

With two parameters the landscape is a surface, drawn below as a contour map: each line joins points of equal loss, and darker shading means higher loss. Three optimizers race from the same start:

  • Gradient descent: the plain rule above.
  • Momentum: keeps a running velocity, like a heavy ball. Consistent directions build speed; zig-zags cancel out.
  • Adam: momentum plus a per-parameter step size that adapts to how large that parameter's gradients have been. The default optimizer for deep learning.

Batches, epochs, and useful noise

Computing the exact gradient needs the whole dataset, which may be millions of examples. Instead we estimate it from a small random mini-batch:

VariantGradient fromCharacter
Batch GDAll examplesAccurate, smooth, slow per step, needs the data in memory.
Stochastic GD (SGD)One exampleVery noisy, very cheap per step.
Mini-batch GD32 to a few thousand examplesThe practical default. Fits GPU parallelism well.

One pass through the whole training set is an epoch. The noise from mini-batches is not just tolerated, it helps: it can knock the optimizer out of sharp, narrow minima into wider ones, and wide minima tend to generalize better.

Learning rate schedules

Big steps help early, small steps help at the end to settle into the minimum. So the rate usually changes over training: a short warmup that ramps up from near zero (stabilizes early training of large networks), followed by decay, commonly a cosine curve down toward zero.

What about local minima?

In two dimensions local minima look scary. In the millions of dimensions of real networks, true bad local minima turn out to be rare: to trap you, a point must curve upward in every one of a million directions at once. More common are saddle points and flat plateaus, which momentum and noise help escape. For convex problems such as linear and logistic regression there is only one minimum, so gradient descent finds the global optimum.

Your training loss jumps around wildly and then becomes NaN. What should you try first?

Exploding loss is the classic symptom of steps that overshoot. Lower the learning rate (and check your data for extreme values).

What is an epoch?

With 10,000 examples and batch size 100, one epoch is 100 gradient steps.

Why does plain gradient descent zig-zag in a long, narrow valley?

In a narrow valley the steep walls dominate the gradient. Steps bounce between the walls while progress along the gentle floor is slow. Momentum and Adam, or simply scaling features, fix this.

Logistic regression

Despite the name, it is a classifier. It predicts the probability that an example belongs to a class, and it is the direct ancestor of the neuron.

Suppose we want to predict pass or fail from hours studied. Labels are 0 (fail) and 1 (pass). We could fit a straight line, but a line shoots below 0 and above 1, which makes no sense as a probability, and a few extreme students would tilt it badly. We want an S-shaped curve that stays between 0 and 1.

The sigmoid

Logistic regression computes the same weighted sum as linear regression, then squashes it through the sigmoid function:

σ(z) = 11 + e−z     p = σ(w · x + b)Large positive z gives p near 1, large negative z gives p near 0, and z = 0 gives exactly 0.5.

Log loss: punishing confident mistakes

For classification we do not use squared error. We use log loss, also called binary cross-entropy:

L = −1n Σi [ yi log pi + (1 − yi) log(1 − pi) ]

It reads more simply than it looks: for each example, take the probability the model gave to the correct answer, and add −log of it. Predicting 0.9 for the truth costs 0.1. Predicting 0.5 costs 0.69. Predicting 0.01 for the truth costs 4.6. Being confidently wrong is catastrophically expensive, which is exactly the pressure we want.

Combined with a sigmoid, squared error gives a bumpy, non-convex loss with tiny gradients when the model is confidently wrong, the moment it most needs to learn. Log loss gives a convex bowl and a gradient that is beautifully simple: ∂L/∂z = p − y, prediction minus truth.

Boundaries in two dimensions

With two features the decision boundary w1x1 + w2x2 + b = 0 is a straight line. Logistic regression is a linear classifier. That is a strength (simple, fast, stable, interpretable) and a limitation, as the figure shows.

Feature engineering can turn a linear model into a non-linear one. Neural networks take this to its conclusion: instead of you inventing x² and xy, hidden layers learn which features to build.

The loss becomes cross-entropy: −log of the probability assigned to the true class. Softmax plus cross-entropy is the output layer of practically every classification network, including the one inside a language model choosing the next word from 100,000 candidates.

Reading the model

Each weight shifts the log-odds log(p / (1 − p)). So ew is an odds ratio: a weight of 0.7 on "hours studied" means each extra hour multiplies the odds of passing by e0.7 ≈ 2. This interpretability is why logistic regression is still standard in medicine, credit scoring and anywhere decisions must be explained.

Measuring what matters

A model is only as good as the number you judge it by. Pick the wrong metric and you will optimize the wrong thing with great precision.

Accuracy lies

A fraud dataset has 1 fraudulent transaction per 100. A "model" that always answers "not fraud" scores 99% accuracy and catches nothing. Whenever classes are imbalanced, and in real problems they usually are, accuracy hides failure. You need to look at the kinds of mistakes separately.

The confusion matrix

Every binary prediction lands in one of four boxes:

From these four counts come the metrics you will use daily:

  • Precision = TP / (TP + FP): when the model says positive, how often is it right? Low precision means false alarms.
  • Recall (sensitivity, true positive rate) = TP / (TP + FN): of all real positives, how many did we catch? Low recall means misses.
  • F1 = 2PR / (P + R): the harmonic mean, high only when both are high.
  • False positive rate = FP / (FP + TN): the share of negatives wrongly flagged.

The threshold trade-off

A classifier outputs a score. You choose the threshold above which you call it positive. Move the threshold and you trade one kind of error for the other. There is no free lunch, only a business decision about which mistake costs more.

Favor recall

Cancer screening

Missing a case is far worse than a false alarm followed by a second test. Use a low threshold.

Favor precision

Spam filter

Hiding a real email from your boss is worse than letting some spam through. Use a high threshold.

Explicit costs

Fraud review

Each flag costs analyst time; each miss costs money. Pick the threshold that minimizes total expected cost.

ROC and AUC

The ROC curve plots true positive rate against false positive rate across every threshold. The AUC (area under it) summarizes the model independent of threshold, and has a lovely meaning: the probability that a randomly chosen positive gets a higher score than a randomly chosen negative. 0.5 is coin-flipping, 1.0 is perfect ranking.

When positives are rare, prefer the precision-recall curve and its area (average precision). It exposes exactly the false-alarm flood the ROC curve hides.

Probabilities should mean what they say

If a model says "70% chance" for a thousand cases, about 700 should turn out positive. A model with this property is calibrated. Ranking metrics like AUC ignore calibration entirely, but it matters whenever probabilities feed decisions or pricing. Modern neural networks are often over-confident; techniques like Platt scaling, isotonic regression or temperature scaling fix calibration after training.

Always have a baseline

Before celebrating a score, compute what a trivial approach gets: predict the most common class, predict the mean, predict "same as last week". A model that barely beats its baseline is not worth its complexity. A shocking number of production projects never check.

Validation scores are noisy. If model A scores 0.842 and B scores 0.838 on 500 examples, that gap is well inside the noise. Use cross-validation (look at the spread across folds) or bootstrap confidence intervals before declaring a winner.

Overfitting and regularization

The central tension of machine learning: a model flexible enough to capture real patterns is also flexible enough to memorize noise.

Imagine two students preparing for an exam with last year's questions. One memorizes every answer word for word. The other learns the underlying ideas. On last year's paper both score 100%. On this year's paper the memorizer collapses. A model that memorizes its training data is said to overfit; one too simple to capture the pattern at all underfits.

Training error always goes down as models get more flexible. Test error goes down, then up. Never judge a model by its training error. The gap between training and validation error is your overfitting gauge.

Bias and variance

Two different things can go wrong, and it helps to name them:

  • Bias: error from wrong assumptions. A straight line fit to a curve is wrong no matter how much data you give it. High bias means underfitting.
  • Variance: error from sensitivity to the particular training sample. Press "New sample" at degree 12: the curve changes completely each time. High variance means overfitting.

How to fight overfitting

  1. Get more data. The most reliable fix. With enough points even a degree-14 polynomial is pinned down.
  2. Use a simpler model or fewer features. Match capacity to the amount of data.
  3. Regularize: add a penalty for complexity to the loss, so the model only uses large weights when the data truly demands it.
  4. Stop early: watch validation loss during training and stop when it starts rising.
  5. Augment: create more training examples by transforming existing ones (flip, crop, add noise). Standard for images and audio.
  6. Average many models: ensembles cancel out individual models' variance (chapter 10).

L2 and L1 regularization

Regularization adds a term to the loss that grows with the size of the weights, controlled by strength λ:

Lridge = MSE + λ Σ wj²      Llasso = MSE + λ Σ |wj|
  • L2 (ridge, weight decay) shrinks all weights smoothly toward zero. Wiggly curves need huge coefficients, so penalizing size penalizes wiggles. This is what the λ slider does.
  • L1 (lasso) pushes many weights to exactly zero, performing automatic feature selection. Useful when you suspect only a few of many features matter.
  • Elastic net mixes both.

λ is a hyperparameter: too small and you still overfit, too large and you underfit. You choose it with the validation set or cross-validation.

Diagnose with learning curves

Plot training and validation error as the training set grows:

  • Both errors high and close together: high bias. More data will not help. Use a more flexible model or better features.
  • Low training error, a big gap to validation: high variance. More data, regularization or a simpler model will help.

Huge neural networks have far more parameters than training examples, yet often generalize well. Researchers observed double descent: past the point where a model can exactly fit the training data, test error can fall again as size grows. Implicit regularization from gradient descent, plus explicit tricks like weight decay and data augmentation, explain much of it. The classic U-curve is still the right mental model for most everyday work.

k-nearest neighbors

The simplest classifier that works: to label something new, find the most similar examples you already know and let them vote.

k-NN has no training phase at all. It stores the dataset. At prediction time it measures the distance from the new point to every stored example, takes the k closest, and returns the majority class (or the average value, for regression). It is called a lazy or instance-based learner: all the work happens at prediction time.

Choosing k

k is the model's complexity dial, and it runs backward from what you might expect: small k means a complex, jagged boundary (low bias, high variance), large k means a smooth one (high bias, low variance). As with every hyperparameter, pick it with validation data, never with training accuracy. With k = 1 the training accuracy is always 100%, since each point is its own nearest neighbor.

Distance is everything

  • Euclidean: straight-line distance, √Σ(ai − bi)². The default.
  • Manhattan: sum of absolute differences, like walking city blocks. Less dominated by one large difference.
  • Cosine: compares direction, ignoring length. Standard for text and embeddings.

Because it lives on distances, k-NN is the algorithm most wrecked by unscaled features. Always standardize first (you saw why in chapter 03).

The curse of dimensionality

Nearest neighbors breaks down as the number of features grows, for a strange geometric reason: in high dimensions, everything is far from everything, and the nearest neighbor is barely nearer than the farthest. To capture 10% of the data around a point in 1 dimension you need a neighborhood spanning 10% of the range. In 10 dimensions you need 79% of the range along every axis. "Local" stops meaning anything.

At scale it runs on approximate nearest neighbor indexes (HNSW graphs, libraries like FAISS) inside vector databases, which trade a tiny bit of accuracy for searches over billions of vectors in milliseconds.

Decision trees and ensembles

A tree asks a sequence of yes/no questions. One tree is readable but fragile. Hundreds of trees combined are among the most powerful tools for tabular data that exist.

A game of twenty questions

A decision tree predicts by walking from the root to a leaf, answering one question per node: "Is income above 52k? Is age below 30?" Each leaf holds a prediction: the majority class of the training examples that ended up there (or their average value, for regression). You can print a tree and hand it to a colleague, and they can follow it by hand.

How a tree picks its questions

Training is greedy. At each node, try every feature and every threshold, and pick the split that makes the two child groups as pure as possible. Purity is measured by Gini impurity (or entropy):

Gini = 1 − Σk pk²0 for a group of one class only; 0.5 for a 50/50 mix of two classes.

Then repeat inside each child, recursively, until the groups are pure or a stopping rule kicks in: a maximum depth, or a minimum number of samples per leaf. Regression trees use the same procedure with variance instead of Gini.

Ensembles: the wisdom of crowds

If you average many models whose errors are at least partly independent, the errors cancel and the average is better than any individual. The two great ways to build tree ensembles are bagging and boosting.

Bagging and random forests

Bagging (bootstrap aggregating) trains each tree on a random sample of the data drawn with replacement, then averages their votes. A random forest adds one more twist: at each split, a tree may only consider a random subset of features. That forces the trees to be different from one another, which makes the averaging far more effective. Random forests are hard to break, need little tuning, and are a superb first model for almost any table of data.

Bonus: each tree skips about a third of the examples in its bootstrap sample. Predicting those out-of-bag examples gives a free validation score.

Boosting

Boosting builds trees in sequence instead of in parallel. Each new tree is trained to fix the mistakes of all the trees before it. In gradient boosting, each tree is fitted to the residuals (the remaining errors), and its prediction is added in with a small weight ν, the learning rate:

Fm(x) = Fm−1(x) + ν · treem(x)

For squared error, the residual y − F(x) is exactly the negative gradient of the loss with respect to the prediction. So each tree takes one gradient descent step, not in parameter space but in function space. Swap in another loss's gradient and the same machinery handles classification, ranking or any differentiable objective.

XGBoost, LightGBM and CatBoost are the industrial-strength gradient boosting libraries. On tabular data they routinely beat deep learning and win a large share of Kaggle competitions. Key hyperparameters: number of trees, learning rate (smaller is better but slower), max depth (3 to 8 is typical), row and column subsampling, and early stopping on a validation set to pick the number of trees automatically.

Which features matter?

  • Impurity importance (the built-in feature_importances_): fast, but biased toward features with many unique values.
  • Permutation importance: shuffle one feature in the validation set and measure how much the score drops. Model-agnostic and more trustworthy.
  • SHAP values: split each individual prediction into per-feature contributions. The standard for explaining tree ensembles to stakeholders.

Support vector machines

If many lines separate two classes, pick the one with the widest safety margin. Then bend space so that a straight line can separate almost anything.

The widest street

When two classes can be separated by a line, there are infinitely many lines that do it. Logistic regression picks one based on probabilities. A support vector machine picks the line that sits in the middle of the widest possible "street" between the classes. A wide margin means small nudges to the data will not flip predictions, which tends to generalize well.

The remarkable part: the street is defined entirely by the few points touching its edges, the support vectors. Every other point could be deleted or moved (without crossing the street) and the answer would not change at all.

Soft margins and the C parameter

Real data overlaps, so the SVM is allowed to let points into the street or even across it, at a price. It minimizes the hinge loss plus a penalty on weight size:

λ||w||² + 1n Σi max(0, 1 − yi(w · xi + b))Labels are ±1. A point well on the correct side contributes zero, which is why only support vectors matter.

Small ||w|| means a wide margin (the width is 2 / ||w||). In libraries the trade-off is set by C, which behaves like 1/λ: big C, low tolerance for violations, higher risk of overfitting.

The kernel trick

What if no straight line can separate the classes? Look at the one-dimensional data below: one class sits in the middle, the other on both sides. No single threshold splits them. But add a feature, x², and the data lifts onto a parabola where a flat line separates it perfectly.

Computing huge feature expansions explicitly would be expensive. The trick is that the SVM's math only ever needs dot products between examples, and for many useful feature maps the dot product in the big space can be computed directly from the original vectors. That shortcut function is a kernel:

  • Polynomial kernel (x · z + 1)d: implicit polynomial features of degree d.
  • RBF (Gaussian) kernel exp(−γ ||x − z||²): similarity that decays with distance. It corresponds to an infinite-dimensional feature space and can carve out almost any boundary. γ sets how local each point's influence is; large γ overfits.

SVMs were the state of the art in the 2000s. Today they remain strong for small to medium datasets, and linear SVMs are still excellent for high-dimensional sparse data such as text classification with word counts. Kernel SVMs scale poorly past roughly 100,000 examples, and gradient-boosted trees or neural networks usually take over. Always scale features first: the margin is a distance.

Naive Bayes

A classifier built directly on Bayes' rule, with one deliberately wrong assumption that makes it fast, tiny and surprisingly good. It powered the first generation of spam filters.

Classifying with Bayes' rule

In chapter 02 you used Bayes' rule to flip a conditional probability. A classifier wants P(class | features), and Bayes' rule rewrites it in terms of things we can count in training data:

P(spam | words) ∝ P(words | spam) · P(spam)∝ means "proportional to": we compute this for each class and normalize so they sum to 1.

P(spam) is easy: the share of training messages that are spam. P(words | spam) is hard: the probability of this exact combination of words would need an astronomically large dataset.

The naive assumption

Naive Bayes assumes every feature is independent of the others once you know the class. Then the joint probability splits into a simple product:

P(w1, …, wn | spam) ≈ P(w1 | spam) · P(w2 | spam) · … · P(wn | spam)

The assumption is obviously false ("free" and "prize" appear together far more than chance), but for classification you only need the right class to win, not correct probabilities, and it often does.

Two practical details

  • Work in log space. Multiplying hundreds of small probabilities underflows to zero on a computer. Adding their logarithms is stable, and turns the model into a sum of per-word scores, which is exactly what the bars show.
  • Laplace smoothing. A word never seen in spam would get probability zero and veto the class no matter what else the message says. Adding 1 to every count prevents that.

Naive Bayes is a generative model: it models how the data of each class is produced, P(x | y), and could in principle generate fake emails. Logistic regression is discriminative: it models only the boundary, P(y | x). Discriminative models usually win with plenty of data; generative ones cope better with very little. Today's "generative AI" is the same idea scaled up enormously: models of P(x) rich enough to sample convincing new text and images.

  • Trains in one pass over the data, predicts instantly, works with tiny datasets and huge vocabularies.
  • A strong, honest baseline for any text task. If your transformer barely beats Naive Bayes, question the transformer.
  • Its probabilities are badly calibrated: correlated words get counted several times, pushing outputs toward 0% or 100%. Use it for ranking and decisions, not for trustworthy confidence.

Clustering

No labels, no right answers. Just data, and the question: which of these things belong together?

Most of the world's data has no labels. Clustering finds groups of similar examples on its own: customer segments for marketing, families of similar documents, groups of genes that behave alike, typical patterns of sensor readings. It is also a powerful exploration tool: cluster first, then look at what each cluster has in common.

k-means

The most widely used clustering algorithm fits in four lines:

  1. Pick k, the number of clusters, and drop k centers somewhere.
  2. Assign every point to its nearest center.
  3. Update every center to the average position of its assigned points.
  4. Repeat steps 2 and 3 until nothing changes.

Each step can only reduce the total squared distance from points to their centers, called the inertia, so the algorithm always converges. Not necessarily to the best answer, though.

Choosing k

  • Elbow method: inertia always falls as k grows (k = number of points gives zero), so look for the bend where extra clusters stop paying off.
  • Silhouette score: for each point, compares the distance to its own cluster with the distance to the nearest other cluster. Ranges from −1 to 1; higher is better.
  • The business question: often the decisive factor. A marketing team that can run four campaigns needs four segments.

k-means quietly assumes clusters are round blobs of similar size and density, because it only uses distance to a center. Try "Uneven" and "Moons" in the figure: it slices the big blob in two and cuts the moons straight across. It is also sensitive to feature scale and to outliers, which drag centers around.

DBSCAN: clusters as dense regions

DBSCAN defines clusters by density instead of centers. A point is a core point if at least minPts points (itself included) lie within distance eps. Core points that are within reach of each other chain together into one cluster. Points near a cluster but not dense themselves are border points; everything else is noise.

Hierarchical clustering

Agglomerative clustering starts with every point as its own cluster and repeatedly merges the two closest clusters. The full history of merges forms a tree called a dendrogram; cutting it at different heights gives different numbers of clusters. It is great for small datasets where the nested structure itself is interesting (species, document topics), but costs at least O(n²) memory.

Soft clustering and anomalies

Gaussian mixture models generalize k-means: each cluster is a stretched bell shape, and each point gets a probability of belonging to each cluster rather than a hard label. Closely related, anomaly detection flags points that fit no group well: DBSCAN's noise points, points with low probability under a mixture model, or the output of dedicated methods like isolation forests, which isolate outliers with few random splits.

With no labels there is no accuracy to compute. Clusters are "good" if they are stable (similar when you re-run on resampled data) and useful for the decision at hand. Always inspect examples from each cluster and describe them in plain words. If you cannot, the clusters probably are not meaningful.

More centers always fit better, so you look for diminishing returns (the elbow) or use silhouette and domain knowledge.

Dimensionality reduction

Real datasets have hundreds or thousands of features, but the interesting variation often lives in just a few directions. Find them, and you can compress, denoise and visualize.

Why throw information away on purpose?

  • To see: you can only plot two or three dimensions. Squashing 50 features into 2 lets you look at your data.
  • To fight the curse of dimensionality: fewer, more informative features help distance-based models and reduce overfitting.
  • To compress and denoise: small directions of variation are often just noise.
  • To speed things up: fewer features, faster training.

Principal component analysis

PCA finds new axes for your data. The first principal component is the direction along which the data varies the most. The second is the direction of most remaining variation, perpendicular to the first, and so on. Keep the first few components and drop the rest.

How many components?

Each component comes with the amount of variance it captures. The explained variance ratio tells you what fraction of the total each one keeps. A common rule is to keep enough components for 90 to 95% of the variance. On images of faces or handwritten digits, a few dozen components out of hundreds of pixels often suffice.

The principal components are the eigenvectors of the covariance matrix of the data, and the variance along each is its eigenvalue. Libraries compute them with the singular value decomposition (SVD) of the centered data matrix, which is faster and numerically stable. The matrix-as-transformation picture from chapter 02 is exactly what is happening: PCA rotates your axes to line up with the data.

  • Standardize first. PCA chases variance, so a feature measured in large units will dominate the first component for no good reason.
  • Components are blends. PC1 might be 0.4 × income + 0.3 × age − 0.2 × debt. That is harder to explain than the original features.
  • Linear only. PCA finds flat subspaces. Data curled up on a curved surface needs non-linear methods.

Non-linear methods for visualization

t-SNE and UMAP build 2D maps where points that are neighbors in the original space stay neighbors. They produce striking pictures of clusters in images, text embeddings and single-cell biology. Read them carefully: they preserve local neighborhoods, so the sizes of clusters and the distances between clusters on the map usually mean nothing. Use them to look, not to measure.

Learned compression

An autoencoder is a neural network trained to reproduce its input through a narrow middle layer. To succeed it must learn a compact code, a non-linear generalization of PCA. The idea of learning compact, meaningful vector representations, called embeddings, runs through all of modern deep learning and returns in chapter 18.

Neural networks and backpropagation

Stack many simple units, each a weighted sum followed by a bend, and train them all at once with the chain rule. That is the entire foundation of deep learning.

The artificial neuron

You have already met the neuron: it is logistic regression. It takes inputs, multiplies each by a weight, adds a bias, and passes the result through an activation function:

a = f(w1x1 + w2x2 + … + wnxn + b) = f(w · x + b)

Why the bend matters

Without an activation function, a neuron is linear, and stacking linear layers gives... another linear function. Ten layers of matrix multiplications collapse into a single matrix. The non-linear activation is what lets depth add expressive power: each layer can fold and bend the space that the next layer sees.

Layers

A layer is many neurons reading the same inputs, each with its own weights. In matrix form a whole layer is one line, which is why GPUs are so good at this:

h = f(W x + b)W holds one row of weights per neuron. The output h is a new vector: the input re-described by learned features.

A multilayer perceptron (MLP) chains layers: input, one or more hidden layers, and an output layer. The output uses a sigmoid for binary classification, a softmax for multiple classes, or nothing (identity) for regression. The hidden layers learn their own features, the thing you did by hand with x² in chapter 06.

A network with a single hidden layer and enough neurons can approximate any reasonable continuous function as closely as you like. The theorem guarantees the capacity exists; it says nothing about how many neurons, how much data, or whether training will find the weights. In practice, depth (many layers) reaches the same power far more efficiently than width.

Backpropagation

Training needs the gradient of the loss with respect to every weight, possibly billions of them. Backpropagation computes all of them in one backward sweep, at about the cost of one forward pass. It is nothing but the chain rule applied systematically:

  1. Forward pass: compute and remember every intermediate value, from input to loss.
  2. Backward pass: start at the loss with gradient 1. At each operation, multiply the gradient arriving from above by the operation's local derivative and pass it down to its inputs.
  3. Update: every parameter now knows its gradient; take an optimizer step.

Frameworks like PyTorch and JAX build this graph automatically as your code runs (automatic differentiation), so you never derive gradients by hand. Understanding the mechanics still matters: it explains vanishing and exploding gradients, why some operations break training, and what loss.backward() actually does.

Andrej Karpathy's free "Neural Networks: Zero to Hero" course begins by writing a tiny autograd engine (micrograd) in about 100 lines of Python. After that, nothing in PyTorch feels like magic. Highly recommended as your next step after this guide.

What happens if you stack many layers with no activation functions?

A product of matrices is still a matrix. Without non-linearity, depth adds no expressive power.

In backpropagation, what does a multiplication node z = w · x pass back to w?

∂z/∂w = x, so by the chain rule w receives (upstream gradient) × x. Each input gets the other input as its local derivative.

Why did ReLU largely replace sigmoid in hidden layers?

Sigmoid's derivative is at most 0.25, so gradients shrink exponentially through many layers. ReLU passes gradient 1 for positive inputs and is also cheaper to compute.

Training deep networks

A real neural network, training live in your browser. Then the practical craft: the settings, tricks and warning signs that decide whether a network learns or flails.

Experiments worth running

  1. Depth vs. no depth. Circle data with 0 hidden layers is logistic regression: it fails. Add one hidden layer with 3 or more neurons and it succeeds. Or keep 0 layers and turn on x₁² and x₂²: hand-made features do the same job.
  2. The spiral. Try it with 2 layers of 4: it struggles. Give it 3 or 4 layers of 8, or the sine features, and be patient.
  3. Linear activation. Choose "Linear" with 4 layers on the circle. No amount of depth helps, exactly as chapter 15 predicted.
  4. Learning rate. Set it to 1 with SGD and watch the loss thrash. Set it to 0.001 and watch it crawl.
  5. Overfitting. Noise at 0.8, 4 layers of 8 neurons, and let it run. Training loss keeps falling, test loss turns upward, and the boundary grows islands around individual noisy points. Now add L2 regularization.
  6. Dead ReLUs. Pick ReLU with a high learning rate and watch some neuron squares go blank: they output zero everywhere and have stopped learning.

Initialization

Weights start random, never all zero: identical weights would make every neuron in a layer compute the same thing and receive the same gradient forever (the symmetry problem). The scale matters too. Too large and activations explode or saturate; too small and signals fade to nothing after a few layers. Xavier/Glorot initialization (for tanh) and He initialization (for ReLU) scale the random weights by the number of inputs so that signal strength stays roughly constant through the layers. Frameworks do this by default.

Normalization layers

Batch normalization rescales each layer's outputs to zero mean and unit variance over the mini-batch, then lets the network learn its preferred scale and shift. It makes training faster and far less sensitive to initialization and learning rate. Layer normalization does the same across the features of a single example instead of across the batch, which is what transformers use.

Regularization, deep learning style

  • Weight decay: L2 regularization, usually via the AdamW optimizer.
  • Dropout: during training, randomly switch off a fraction of neurons (say 10 to 50%) at each step. No neuron can rely on any specific other one, which forces redundant, robust features. At test time all neurons are active.
  • Data augmentation: random crops, flips, color jitter, noise. Often the single biggest win for images.
  • Early stopping: keep the checkpoint with the best validation loss.

Reading loss curves

A practical recipe

  1. Look at the data for longer than feels necessary. Check labels, duplicates, class balance, weird values.
  2. Get a dumb baseline working end to end, including evaluation, before any cleverness.
  3. Overfit one small batch. A correct network must be able to drive loss near zero on 10 examples. If it cannot, you have a bug.
  4. Then scale up and add regularization only when validation loss says you need it.
  5. Change one thing at a time and keep a log of every run (tools like Weights & Biases or MLflow help).
  6. Tune the learning rate first; it matters more than almost anything else.

Deep learning runs on GPUs because it is mostly matrix multiplication done in parallel. Larger batches use the GPU better but may need a larger learning rate. Mixed precision (16-bit floats where safe) roughly doubles speed and halves memory. When a model does not fit, reduce batch size, use gradient accumulation, or use a smaller model. Free notebooks (Google Colab, Kaggle) give you a GPU to learn with.

Convolutional neural networks

How machines learned to see: slide small learned filters across an image, detect edges, then shapes, then objects.

Images are grids of numbers

A grayscale image is a matrix of brightness values. A color image is three of them stacked (red, green, blue channels). A modest 224×224 color photo is 150,528 numbers. Feeding that into a regular fully connected layer with 1,000 neurons needs 150 million weights for the first layer alone, and the network would have to learn "a cat in the top left" and "a cat in the bottom right" as unrelated facts.

Convolutional networks fix both problems with two ideas that match how images work:

  • Local connectivity: nearby pixels matter together. Each unit looks only at a small patch.
  • Weight sharing: an edge is an edge wherever it appears. The same small filter is reused at every position.

Convolution

A kernel (or filter) is a small grid of weights, typically 3×3. Place it over a patch of the image, multiply overlapping numbers, and sum them: one output value. Slide it one step and repeat. The grid of outputs is a feature map: a picture of where the pattern the kernel encodes appears.

The building blocks

PieceWhat it does

Embeddings, attention and transformers

The architecture behind ChatGPT, Claude, modern translation and much of today's AI. It rests on two ideas: represent meaning as vectors, and let every word decide which other words matter to it.

From words to vectors

Models need numbers. Text is first split into tokens (words or pieces of words), each token gets an ID, and each ID looks up a learned vector called an embedding, typically with hundreds or thousands of dimensions. Training arranges these vectors so that tokens used in similar contexts end up near each other. Nobody tells the model that "king" and "queen" are related; it discovers it because they appear in similar sentences.

Embeddings are one of the most useful tools in applied ML, even without training anything. Embed product descriptions, support tickets or documents with a pretrained model, then use nearest neighbor search for semantic search, recommendations, deduplication, clustering, or retrieval for a chatbot.

The sequence problem

Meaning depends on context: "bank" in "river bank" versus "bank account". Earlier recurrent neural networks (RNNs, and the improved LSTMs) read text one token at a time, carrying a running memory vector. They worked, but information from far back faded, and processing tokens one after another made training slow and hard to parallelize.

Attention

Self-attention lets every token look at every other token at once and decide how much each one matters to it. Each token produces three vectors from its embedding, using three learned weight matrices:

  • a query q: what am I looking for?
  • a key k: what do I contain?
  • a value v: what will I pass along if chosen?

The relevance of token j to token i is the dot product qi · kj. A softmax turns these scores into weights that sum to 1, and token i's new representation is the weighted average of all the values:

Attention(Q, K, V) = softmax( Q KT√d ) VDividing by √d (the vector size) keeps scores in a range where softmax still has useful gradients.

The transformer block

A transformer stacks identical blocks, each with two parts wrapped in residual (skip) connections and layer normalization:

  • Multi-head attention: several attention mechanisms in parallel, each free to track a different kind of relationship (grammar, coreference, topic).
  • Feed-forward network: an MLP applied to each token separately. Much of the model's stored knowledge is thought to live here.
  • Positional information: attention itself ignores word order, so position is injected into the embeddings (sinusoids, learned vectors, or rotary encodings).
  • Residual connections and layer norm: the ResNet trick from chapter 17, which keeps very deep stacks trainable.

Why transformers took over

All tokens are processed in parallel, which suits GPUs perfectly; any token can reach any other in one step, so long-range context is easy; and performance keeps improving predictably as you add data, parameters and compute (the scaling laws). The same block now handles text, images (Vision Transformers), audio, protein sequences and more.

FlavorAttentionExamples and uses

Every token attends to every other, so compute grows with the square of the sequence length. Doubling the context quadruples the attention work. Much engineering (efficient attention kernels, caching, sparse and linear attention variants) exists to fight this.

In code

import torch, torch.nn.functional as F

def self_attention(x, Wq, Wk, Wv, causal=False):
    # x: (tokens, d_model); W*: (d_model, d_head)
    Q, K, V = x @ Wq, x @ Wk, x @ Wv
    scores = Q @ K.T / K.shape[-1] ** 0.5           # (tokens, tokens) relevance
    if causal:                                       # decoder: no peeking at the future
        mask = torch.triu(torch.ones_like(scores), diagonal=1).bool()
        scores = scores.masked_fill(mask, float("-inf"))
    weights = F.softmax(scores, dim=-1)              # each row sums to 1
    return weights @ V                               # weighted mix of values

x = torch.randn(11, 64)

print(out.shape)   # torch.Size([11, 16])

Large language models

A transformer trained to predict the next token, on a large fraction of the written internet, then taught to be a helpful assistant. Here is what is actually going on, and how people use them at work.

Next-token prediction

A large language model (LLM) is a decoder-only transformer (chapter 18) whose output layer is a softmax over its whole vocabulary, often 50,000 to 200,000 tokens. Given the text so far, it outputs a probability for every possible next token. To write a response it picks one token, appends it, and runs again. Every word you read from a chatbot was produced this way, one token at a time.

The training objective sounds almost trivially simple: predict the next token, measured by cross-entropy (chapter 06). But to predict text well across billions of documents, a model has to pick up grammar, facts, styles, the structure of code, and patterns of reasoning. That compression of the world's text into weights is what makes the result useful.

Tokens

Models do not see characters or words but tokens, produced by algorithms like byte-pair encoding that merge frequent character sequences. Common words are one token; rare words split into pieces: "unbelievably" might become un believ ably. In English a token averages roughly three quarters of a word. Tokens are the unit of everything practical: context window size, speed and price. They also explain some odd failures, like miscounting the letters in a word the model never sees letter by letter.

Choosing the next token

The model outputs probabilities; a decoding strategy turns them into a choice. Always taking the most likely token (greedy decoding) is repetitive and bland. Sampling adds variety, controlled by a few knobs you will see in every LLM API:

  • Temperature divides the scores before the softmax. Below 1 sharpens the distribution (more predictable), above 1 flattens it (more surprising, eventually incoherent).
  • Top-k keeps only the k most likely tokens.
  • Top-p (nucleus sampling) keeps the smallest set of tokens whose probabilities add up to p.

From text predictor to assistant

  1. Pretraining: next-token prediction on trillions of tokens of text and code. This is where nearly all knowledge and capability comes from, and nearly all the compute cost. The result, a base model, continues text but does not follow instructions reliably.
  2. Supervised fine-tuning: continued training on curated examples of instructions paired with high-quality responses. The model learns the format and behavior of an assistant.
  3. Preference tuning: people (or AI feedback guided by written principles) compare pairs of responses; the model is optimized toward the preferred ones. RLHF uses reinforcement learning (chapter 20) for this; methods like DPO optimize preferences directly.

Using LLMs in real work

Prompting

Say what you want

Clear instructions, relevant context, examples of the desired output (few-shot), and a specified format. Cheapest lever; try it first.

RAG

Retrieval-augmented generation

Embed your documents, retrieve the most relevant chunks for each question (k-NN, chapter 09), and put them in the prompt. Grounds answers in your data and reduces made-up facts.

Fine-tuning

Adjust the weights

Train further on your examples to lock in a style, format or narrow skill. Parameter-efficient methods like LoRA train small add-on matrices instead of the whole model.

Agents

Tools and loops

Let the model call functions (search, code execution, databases) and iterate on the results. Powerful, and harder to test and secure.

  • Hallucination: fluent, confident, wrong. The model generates plausible text, not verified truth. Ground it with retrieval and check important outputs.
  • Knowledge cutoff: it only knows what was in its training data unless you provide more in the context.
  • Prompt injection: instructions hidden in documents or web pages the model reads can hijack its behavior. Treat model output that triggers actions as untrusted.
  • Evaluation is hard: build a test set of real inputs with expected outputs (an "eval") before you change prompts or models, exactly like a validation set.

Reinforcement learning

No labeled answers, only consequences. An agent tries things, collects rewards and penalties, and gradually learns which actions pay off in the long run.

The loop

At each step the agent observes a state, picks an action according to its policy, and the environment responds with a new state and a numeric reward. The goal is to maximize the total reward over time, called the return. Rewards can be delayed: a chess move's value may only show twenty moves later. Working out which earlier actions deserve the credit is the core difficulty.

Future rewards are usually discounted by a factor γ between 0 and 1 per step:

G = r1 + γ r2 + γ² r3 + …γ near 1 means patient and far-sighted; γ near 0 means greedy for immediate reward.

Q-learning

One classic approach learns a table of Q-values: Q(s, a) estimates the return you get by taking action a in state s and acting well afterward. If you know Q, the best policy is simply "pick the action with the highest Q". After every step, nudge the estimate toward what just happened:

Q(s, a) ← Q(s, a) + α [ r + γ maxa′ Q(s′, a′) − Q(s, a) ]The bracket is the surprise: the reward received plus the best value of the next state, minus what we expected.

Notice the estimate is built from another estimate, Q(s′, a′). Value information flows backward from the goal, one step at a time, episode by episode.

Explore or exploit?

An agent that always takes the best-known action never discovers better ones. An agent that always explores never cashes in. The simple ε-greedy rule takes a random action with probability ε and the best-known action otherwise, often lowering ε over time. The same dilemma appears in A/B testing and recommendation systems, where it is studied as the multi-armed bandit problem.

Deep reinforcement learning

A table works for 48 grid cells, not for the pixels of a video game or the joint angles of a robot. Deep RL replaces the table with a neural network:

  • DQN (2015): a CNN estimates Q-values from raw screen pixels. It learned dozens of Atari games from score alone.
  • Policy gradient methods train the policy network directly to make high-return actions more likely. PPO is the workhorse, including in RLHF for language models (chapter 19).
  • AlphaGo and AlphaZero combined deep networks, search and self-play to beat world champions at Go and chess.
  • Sample hungry: millions of trials are cheap in a simulator and impossible on real hardware.
  • Reward hacking: agents optimize the reward you wrote, not the one you meant. A famous boat-racing agent learned to spin in circles collecting points instead of finishing the race.
  • Unstable training and high variance between runs; results depend heavily on random seeds.

For most business problems supervised learning is the better tool. Use RL when decisions affect future data and there is a simulator or a safe way to experiment.

In code

import numpy as np
import gymnasium as gym

env = gym.make("FrozenLake-v1", is_slippery=False)
Q = np.zeros((env.observation_space.n, env.action_space.n))
alpha, gamma, eps = 0.5, 0.95, 0.2

for episode in range(2000):
    s, _ = env.reset()
    done = False
    while not done:
        a = env.action_space.sample() if np.random.rand() < eps else int(np.argmax(Q[s]))
        s2, r, terminated, truncated, _ = env.step(a)
        target = r + (0 if terminated else gamma * Q[s2].max())
        Q[s, a] += alpha * (target - Q[s, a])       # the Q-learning update
        s, done = s2, terminated or truncated
print(np.argmax(Q, axis=1).reshape(4, 4))           # learned policy

γ weights rewards k steps ahead by γk. Higher values make the agent value long-term outcomes.

Pure exploitation locks in early, possibly poor, habits. Some exploration is needed to find better strategies.

The ML project workflow

Training the model is maybe a fifth of a real project. The rest is framing the problem, wrangling data, evaluating honestly, shipping, and keeping it working.

1. Frame the problem

The most expensive mistakes happen before any code. Answer these in writing:

  • What data is available at prediction time? (Leakage prevention starts here.)

2 to 4. Data, exploration, baseline

Gather data, and if you need labels, write labeling guidelines and measure how often two labelers agree: if humans disagree 20% of the time, no model will be 99% accurate. Explore distributions, missing values and relationships, and hunt for suspiciously predictive features. Then build the simplest possible end-to-end baseline, from raw data to a metric, so everything later is a measured improvement.

5. Iterate with error analysis

Do not just stare at the aggregate score. Pull 50 to 100 examples the model gets wrong and categorize them by hand. You will find label errors, missing features, confusing classes, and data quirks. This single habit separates effective practitioners from people who try random architectures. Track every experiment (parameters, data version, code version, metrics) so you can reproduce and compare.

6. Evaluate like a skeptic

  • Report on the untouched test set once, at the end.
  • Break metrics down by slices: regions, device types, customer segments, demographic groups. A great average can hide a disaster in one slice.
  • Offline metrics are a proxy. The real test is an online experiment (A/B test) measuring the business outcome.

  • Data drift: input distributions change (new customer types, a sensor replaced, a UI redesign).
  • Concept drift: the relationship itself changes (fraudsters adapt, tastes shift, a pandemic hits).
  • Feedback loops: the model's own decisions shape future training data (a recommender only learns about what it chose to show).

A default playbook

  1. Establish a trivial baseline (majority class, mean, last value) and a simple model (linear/logistic regression).
  2. For tables, try a random forest, then gradient boosting with early stopping.
  3. For images, text and audio, start from a pretrained deep model and fine-tune, or call a foundation model.
  4. Improve the data before the algorithm: fix labels, add informative features, get more examples of the failure cases.
  5. Only then reach for stacking, custom architectures or heavy hyperparameter searches, and only if the extra accuracy is worth the added complexity.

Accuracy is one criterion among several. Latency (must it answer in 10 ms?), cost, the size of your team, explainability requirements, how often the model must be retrained, and who will maintain it next year often decide more than a 0.5% gain in AUC.

You must predict loan default and explain each decision to regulators. What is a sensible first model?

Interpretability requirements favor linear models (or constrained trees). Compare against a boosted model to know what accuracy you are trading away.

Better data beats cleverer algorithms in most practical settings.

Responsible machine learning

Models make decisions about loans, jobs, medical care and what billions of people see. Getting the math right is necessary, not sufficient.

This is not a soft topic bolted onto the technical ones. Bias, privacy failures and unexplainable decisions are engineering defects with legal, financial and human consequences, and regulation such as the EU AI Act now requires many teams to document and test for them. You will be expected to handle these issues at work.

Where bias comes from

  • Historical bias: the data faithfully records an unfair past. A hiring model trained on past hires learns past preferences.
  • Representation bias: some groups are underrepresented, so the model is simply less accurate for them (face recognition error rates that differ by skin tone are a well-documented case).
  • Measurement bias: the label is a flawed proxy. Using "arrests" as a proxy for "crime" bakes in policing patterns; using "healthcare spending" as a proxy for "health need" underestimates need for groups with less access to care.
  • Feedback loops: predictions shape the future data that retrains the model.

Removing a sensitive column (gender, ethnicity) does not remove the bias: zip code, name, school or shopping habits can act as proxies.

Fairness has several definitions

CriterionAsks that
Demographic parityEach group is selected at the same rate.
Equal opportunityTruly qualified people in each group are selected at the same rate (equal true positive rates).
Equalized oddsBoth true positive and false positive rates match across groups.
CalibrationA score of 70% means 70% in every group.

When base rates differ between groups, it is mathematically impossible to satisfy calibration and equalized odds at the same time (except for a perfect model). Choosing a fairness criterion is therefore a value judgment about which errors matter most, to be made with domain experts and affected people, not silently by whoever writes the code.

Explainability

  • Global: which features matter overall (permutation importance, partial dependence plots).
  • Local: why this particular prediction (SHAP values, LIME, counterfactuals like "approved if income were $4,000 higher").
  • By design: when stakes are high, prefer models that are interpretable in the first place.

Explanations are also a debugging tool. A famous example: a model separating wolves from huskies turned out to be detecting snow in the background.

Privacy and security

  • Models can memorize and leak training data, including personal information. Minimize what you collect, anonymize carefully, and control access.
  • Differential privacy adds calibrated noise so that no individual's presence in the data can be inferred. Federated learning trains across devices without centralizing raw data.
  • Adversarial examples (tiny crafted input changes that flip predictions), data poisoning and prompt injection are real attacks. Threat-model ML systems like any other software.

Glossary

Every term from the guide, in plain language. Type to filter.

Accuracy
Share of predictions that are correct. Misleading when classes are imbalanced.
Activation function
The non-linear function applied after a neuron's weighted sum (ReLU, tanh, sigmoid, GELU). Without it, deep networks collapse to linear models.
Adam
An optimizer combining momentum with per-parameter adaptive step sizes. The default for deep learning; AdamW adds decoupled weight decay.
Agent
In reinforcement learning, the decision maker. In LLM applications, a model that calls tools and acts in a loop.
Attention
A mechanism where each token computes weights over all other tokens (query-key dot products plus softmax) and mixes their values accordingly.
AUC (ROC AUC)
Area under the ROC curve: the probability that a random positive is scored higher than a random negative. 0.5 is random, 1.0 perfect.
Autoencoder
A network trained to reconstruct its input through a narrow bottleneck, learning a compressed representation.
Backpropagation
Computing gradients of the loss with respect to all weights by applying the chain rule backward through the network.
Bagging
Bootstrap aggregating: train models on random resamples of the data and average them. The basis of random forests.
Baseline
A simple reference solution (predict the mean, majority class, last value) that any real model must beat.
Batch normalization
Normalizing a layer's outputs over the mini-batch to stabilize and speed up training.
Batch size
Number of examples used to estimate the gradient for one update.
Bias (model)
Systematic error from overly simple assumptions; high bias means underfitting. Also the intercept term b in a linear model or neuron.
Bias (fairness)
Systematically worse or unfair outcomes for some groups, often inherited from data.
Boosting
Building an ensemble sequentially, each model correcting the errors of the previous ones. Gradient boosting fits each new tree to residuals.
Calibration
Whether predicted probabilities match observed frequencies: of cases given 70%, about 70% should be positive.
Chain rule
The derivative of nested functions is the product of their derivatives. The math behind backpropagation.
Class imbalance
When one class is much rarer than others. Calls for suitable metrics, class weights or resampling.
Classification
Supervised learning that predicts a category.
Clustering
Grouping similar examples without labels (k-means, DBSCAN, hierarchical).
CNN
Convolutional neural network: uses small shared kernels slid across the input. The classic architecture for images.
Concept drift
A change over time in the relationship between inputs and target, which degrades deployed models.
Confusion matrix
A table of true positives, false positives, false negatives and true negatives.
Context window
The maximum number of tokens an LLM can consider at once.
Convolution
Sliding a small kernel over an input, computing a weighted sum at each position to produce a feature map.
Cosine similarity
The cosine of the angle between two vectors; compares direction regardless of length. Standard for embeddings.
Cross-entropy
The loss for classification: the negative log of the probability assigned to the true class.
Cross-validation
Splitting training data into k folds and rotating which fold is used for validation, giving a more reliable estimate.
Curse of dimensionality
As features multiply, data becomes sparse and distances lose meaning, hurting many methods.
Data augmentation
Creating extra training examples by transforming existing ones (flips, crops, noise).
Data leakage
Information unavailable at prediction time sneaking into training, producing falsely good validation scores.
DBSCAN
Density-based clustering that finds arbitrarily shaped clusters and marks sparse points as noise.
Decision boundary
The surface where a classifier switches from one class to another.
Decision tree
A model that predicts by following a sequence of feature threshold questions to a leaf.
Deep learning
Machine learning with neural networks of many layers.
Derivative
The rate of change of a function; the slope of its tangent line.
Diffusion model
A generative model that learns to reverse a gradual noising process, used for image generation.
Dimensionality reduction
Representing data with fewer features while keeping as much structure as possible (PCA, UMAP).
Dot product
Sum of products of matching vector entries. Measures alignment; the core operation of linear models and neurons.
Dropout
Randomly disabling neurons during training so the network cannot rely on any single one; a regularizer.
Early stopping
Stopping training when validation performance stops improving.
Embedding
A learned vector representing an item (word, product, user) so that similar items are close.
Ensemble
Combining several models to get better, more stable predictions.
Epoch
One full pass over the training data.
Epsilon-greedy
Exploration strategy: random action with probability ε, best-known action otherwise.
Evaluation set (eval)
A fixed collection of inputs with expected outputs used to measure a model or prompt, especially for LLM applications.
F1 score
Harmonic mean of precision and recall.
Feature
An input variable describing an example.
Feature engineering
Creating informative features from raw data using domain knowledge.
Fine-tuning
Continuing to train a pretrained model on a smaller, task-specific dataset.
Foundation model
A large model pretrained on broad data that can be adapted to many tasks (LLMs, vision-language models).
Generalization
Performing well on new, unseen data. The real goal of ML.
Gini impurity
A measure of how mixed the classes in a node are; trees choose splits that reduce it.
Gradient
The vector of partial derivatives; points in the direction of steepest increase.
Gradient descent
Iteratively moving parameters against the gradient to reduce the loss.
Hallucination
A fluent but false output from a generative model.
Hyperparameter
A setting chosen before training (learning rate, depth, k), tuned on validation data.
Inference
Using a trained model to make predictions.
k-means
Clustering by alternately assigning points to the nearest of k centers and moving centers to their points' mean.
k-nearest neighbors
Predicting from the labels of the k most similar training examples.
Kernel (SVM)
A function computing dot products in an implicit high-dimensional feature space, enabling non-linear boundaries.
Kernel (CNN)
A small grid of learned weights slid across an image; also called a filter.
L1 / L2 regularization
Penalties on the absolute (L1, lasso) or squared (L2, ridge, weight decay) size of weights. L1 produces sparse models.
Label
The known answer for a training example; the target.
Large language model (LLM)
A very large transformer trained on next-token prediction over huge text corpora, then tuned to follow instructions.
Learning rate
The step size in gradient descent; the most important training hyperparameter.
Linear regression
Predicting a number as a weighted sum of features, fit by minimizing squared error.
Log loss
Binary cross-entropy; penalizes confident wrong probabilities heavily.
Logistic regression
A linear model passed through a sigmoid to output a class probability.
LoRA
Low-rank adaptation: fine-tuning by training small added matrices instead of all weights.
Loss function
A number measuring how wrong the model is; training minimizes it.
MAE / MSE / RMSE
Mean absolute error, mean squared error, and its square root: standard regression metrics.
Mini-batch
A small random subset of training data used for one gradient step.
MLOps
Practices and tools for deploying, monitoring and maintaining ML systems in production.
Momentum
An optimizer technique that accumulates past gradients as velocity to speed up and smooth descent.
Naive Bayes
A probabilistic classifier using Bayes' rule with the assumption that features are independent given the class.
Neural network
Layers of neurons, each a weighted sum followed by an activation, trained with backpropagation.
One-hot encoding
Representing a category as a vector of 0s with a single 1.
Overfitting
Fitting training data, including its noise, so closely that performance on new data suffers.
Parameter
A number inside the model learned during training (a weight or bias).
PCA
Principal component analysis: projecting data onto the directions of greatest variance.
Pipeline
A chained sequence of preprocessing and modeling steps fit and applied together, preventing leakage and skew.
Policy
In reinforcement learning, the rule mapping states to actions.
Pooling
Downsampling a feature map by summarizing blocks, usually with their maximum.
Precision
Of the items predicted positive, the share that truly are.
Pretraining
Training a large model on broad data with a generic objective before adapting it.
Prompt injection
An attack where instructions hidden in content an LLM reads hijack its behavior.
Q-learning
A reinforcement learning algorithm that learns the expected return of each action in each state.
R²
Fraction of target variance explained by a regression model.
RAG
Retrieval-augmented generation: retrieving relevant documents and adding them to an LLM's prompt.
Random forest
An ensemble of decision trees trained on bootstrap samples with random feature subsets, averaged.
Recall
Of the truly positive items, the share the model caught. Also called sensitivity or true positive rate.
Regression
Supervised learning that predicts a number.
Regularization
Any technique that discourages overly complex models to improve generalization.
Reinforcement learning
Learning to act by trial and error from rewards.
ReLU
Rectified linear unit, max(0, z). The most common hidden-layer activation.
Residual (connection)
Adding a layer's input to its output so gradients flow through very deep networks. Also: a prediction error, y minus y hat.
RLHF
Reinforcement learning from human feedback: tuning a model toward responses people prefer.
ROC curve
True positive rate plotted against false positive rate across all thresholds.
SHAP
A method that attributes each prediction to feature contributions, based on Shapley values.
Sigmoid
The S-shaped function 1 / (1 + e-z) mapping any number into (0, 1).
Softmax
Turns a vector of scores into probabilities that sum to 1.
Standardization
Rescaling a feature to mean 0 and standard deviation 1.
Supervised learning
Learning from examples paired with correct answers.
Support vector machine
A classifier that finds the maximum-margin boundary, determined by the support vectors.
Temperature
A sampling setting that sharpens (low) or flattens (high) a model's output distribution.
Test set
Held-out data used once at the end to estimate real-world performance.
Token
A unit of text (word or word piece) that language models read and produce.
Top-k / top-p sampling
Restricting sampling to the k most likely tokens, or to the smallest set whose probabilities sum to p.
Transfer learning
Reusing a model trained on one task as the starting point for another.
Transformer
A neural architecture built from self-attention and feed-forward blocks; the basis of modern LLMs.
Underfitting
A model too simple to capture the real pattern; high error on training and test data alike.
Unsupervised learning
Finding structure in data without labels.
Validation set
Data held out from training and used to compare models and tune hyperparameters.
Vanishing gradient
Gradients shrinking toward zero through many layers, stalling learning in early layers.
Variance (model)
Sensitivity to the particular training sample; high variance means overfitting.
Vector database
A system storing embeddings and answering nearest-neighbor queries quickly, used for semantic search and RAG.
Weight decay
L2 regularization applied during optimization, shrinking weights a little at every step.
