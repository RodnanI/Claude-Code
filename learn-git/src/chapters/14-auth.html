Logging in: the easy way, tokens and SSH

The first time you push, git asks who you are, and your GitHub password will not work there (GitHub stopped accepting account passwords for git in 2021). Here are your options, easiest first.

Pick a method

GitHub's own command-line tool, gh, logs you in through your browser and configures git for you. It is also great for pull requests later.

  1. Install it from cli.github.com: an installer on Windows, brew install gh on macOS, or your Linux package manager.
  2. Start the login and answer its questions: GitHub.com, HTTPS, Yes to authenticating git, and "Login with a web browser". 
    $ gh auth login
  3. Copy the one-time code it prints, press Enter, paste the code into the browser page that opens, and click Authorize.
  4. Done. git push now just works. Check any time with gh auth status.

If you installed Git for Windows with the default options, you already have Git Credential Manager. The first time you push, a window opens asking you to sign in to GitHub in your browser. Approve it, and your login is stored securely for next time. Nothing else to do.

On macOS and Linux you can install Git Credential Manager as well (on macOS: brew install --cask git-credential-manager), or simply use the GitHub CLI option.

An SSH key is a pair of files: a private key that never leaves your computer and a public key you hand to GitHub. Think padlock and key: GitHub gets the padlock (public), you keep the key (private), and only your computer can open it. Set it up once and never type a password again.

  1. Generate a key. Press Enter to accept the default file name. Adding a passphrase is a good idea. 
    $ ssh-keygen -t ed25519 -C "you@example.com"
  2. Print the public key, the file ending in .pub. Never share the other one. 
    $ cat ~/.ssh/id_ed25519.pub
ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAI... you@example.com
  3. Add it to GitHub: Settings, SSH and GPG keys, New SSH key. Paste it and save.
  4. Test it: 
    $ ssh -T git@github.com
Hi you! You've successfully authenticated, but GitHub does not provide shell access.
  5. Use SSH URLs for your remotes: git@github.com:you/recipes.git instead of the https one.

A personal access token is a long random password that you create on GitHub just for git and other tools. It works with https URLs.

  1. Create one: GitHub, Settings, Developer settings, Personal access tokens, Fine-grained tokens, Generate new token. Give it access to the repositories you need, with "Contents: Read and write".
  2. Copy it right away. GitHub shows it only once.
  3. When git asks for your password, paste the token. The username is still your GitHub username.

Treat it exactly like a password: never commit it, never paste it into chats. Tokens expire, so set yourself a reminder.

HTTPS or SSH URLs?

HTTPS

https://github.com/you/recipes.git

Works everywhere, even behind strict company firewalls. Pairs with the GitHub CLI, the browser popup or a token.

SSH

git@github.com:you/recipes.git

Needs the key setup, then never asks again. Some networks block it.

You can switch an existing repository between them at any time:

$ git remote set-url origin git@github.com:you/recipes.git

Error messages, translated

Authentication failed
You typed your account password. Use one of the methods above instead.
Permission denied (publickey)
The SSH key is missing, not added to GitHub, or not the right one. ssh -T git@github.com tests it.
Repository not found
A typo in the URL, a private repository you are not logged in for, or you are logged in as a different account. GitHub says "not found" instead of "forbidden" on purpose, so private repositories stay secret.
Permission to X denied to Y
You are logged in fine, but your account may not push there. Ask to be added as a collaborator, or fork the project.
