Install git and introduce yourself

A few minutes of setup you only ever do once per computer: install git, tell it your name, and pick sensible defaults.

Install it

  1. Download Git for Windows from git-scm.com/downloads and run the installer.
  2. Click Next through almost everything. The defaults are good. Two screens are worth changing:
  3. "Choosing the default editor": pick Visual Studio Code (or Notepad) instead of Vim. Git opens this editor whenever it needs you to type a message, and Vim is famously hard to exit.
  4. "Adjusting the name of the initial branch": choose "Override the default branch name" and type main.
  5. Open Git Bash from the Start menu when it finishes.

The installer also sets up Git Credential Manager, which handles logging in to GitHub later. Keep it.

macOS often has git already, bundled with Apple's developer tools. Open Terminal and run:

$ git --version

A version number means you are done. If instead a window offers to install the command line developer tools, click Install and wait. That gives you git.

Want a newer version? With Homebrew installed: brew install git.

Use your package manager:

# Ubuntu, Debian, Mint
$ sudo apt update
$ sudo apt install git
# Fedora
$ sudo dnf install git
# Arch
$ sudo pacman -S git

Check that it worked. Any version from the last few years is fine:

$ git --version
git version 2.51.0

Tell git who you are

Every commit is stamped with an author name and email. Git refuses to commit until they are set, so do it now:

$ git config --global user.name "Ada Lovelace"
$ git config --global user.email "ada@example.com"
  • --global means "for every repository on this computer". The settings go into a file called .gitconfig in your home folder.
  • Use the same email as your GitHub account, so GitHub can link your commits to your profile.
  • Rather keep your email private? GitHub gives you a no-reply address under Settings, Emails. It looks like 12345+you@users.noreply.github.com, and you can use it here instead.

Defaults worth setting

init.defaultBranch main
New projects start on a branch called main, matching GitHub. Without it, git uses master and prints a long warning.
core.editor
The editor git opens when it wants you to type something, like a commit message. "code --wait" makes that VS Code.
pull.rebase false
What git pull does when both you and GitHub have new work: merge them, the beginner-friendly choice. Without it, git stops and asks. The GitHub stops explain why.
core.autocrlf
Windows ends lines of text differently from macOS and Linux. true on Windows and input elsewhere stops files from looking "changed" when they are not.

Get a decent code editor

You will edit files constantly. Visual Studio Code is free, runs everywhere and has git built in: changed files are colored in the sidebar, and there are buttons for staging, committing and resolving conflicts. Everything you learn here maps directly onto those buttons.

Graphical git apps are fine, and plenty of professionals use them daily. But they hide what is happening underneath. Learn the commands first; after that, any app is just buttons for things you already understand.

What does --global mean in git config --global user.name "Ada"?

Right. Global settings live in ~/.gitconfig and apply to all your repositories. Without --global, a setting applies only to the repository you are in.
