Branches: parallel lines

Branches let you try an idea on the side while the main version stays safe. Draw git history and it looks exactly like a metro map; a branch is simply a new line splitting off.

Why branch?

Say your recipe site works. You want to redesign the layout, which will take a few days and break things along the way. Meanwhile someone reports a typo that needs fixing today. Without branches, the half-finished redesign and the typo fix get tangled together. With branches, the redesign lives on its own line, and main stays clean and working the whole time.

What a branch really is

The part most people get wrong: a branch is not a copy of your files. It is a lightweight label, a sticky note with a name on it, pointing at one commit. Creating one is instant and costs nothing.

When you commit, git makes the new commit and moves the label of the branch you are on forward onto it. HEAD is how git knows which label that is.

The commands

git branch
List branches. The one marked * is where you are.
git branch name
Create a branch at the current commit, but stay where you are.
git switch name
Move onto a branch. Your files change to match it.
git switch -c name
Create a branch and switch to it in one go. The one you will use most.
git switch -
Jump back to the branch you were on before.
git branch -m new-name
Rename the current branch.
git branch -d name
Delete a branch that has been merged. -D forces it even if it has not. Careful.

Older tutorials use git checkout name and git checkout -b name. Those still work fine. git switch arrived in 2019 because checkout did too many unrelated jobs. Same result, clearer name.

Switching changes your files

When you switch branches, git rewrites the files in your folder to match the commit that branch points at. Files that only exist on the other branch disappear from your folder (they are safe in history) and come back when you switch back. It feels like a magic trick the first time. You will see it in the mission below.

If you have uncommitted edits, git carries them over to the new branch when that is safe. If switching would overwrite them, git refuses with "Your local changes would be overwritten". Commit the work, or stash it, then switch.

Practice

Naming branches

  • Describe the work: add-dark-mode, fix-login-crash, update-readme.
  • Lowercase words joined by dashes. Spaces are not allowed.
  • Many teams use prefixes like feature/search or fix/menu-typo. Slashes are allowed.
