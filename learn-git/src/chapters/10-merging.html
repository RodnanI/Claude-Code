Merging lines back together

A branch is only useful if its work can come back. Merging takes the commits from one branch and brings them into another.

The one rule to remember

You always merge into the branch you are on. To bring feature into main: go to main first, then merge feature.

$ git switch main
$ git merge feature

Depending on what happened on each branch, git merges in one of two ways.

Fast-forward: main did not move

If main got no new commits since the branch split off, there is nothing to combine. Git just slides the main label forward to where feature is. That is a fast-forward. Run the steps and watch the main label.

Three-way merge: both moved

If both branches got new commits, git combines them. It compares three versions (the two branch tips and the commit where they split, hence "three-way") and works out the combined result. It records that in a new merge commit with two parents. On the map it is an interchange station.

In a real terminal, git opens your editor with a ready-made message like Merge branch 'feature' for the merge commit. Just save and close it. The practice terminal fills it in for you.

After merging: delete the branch

Once merged, the branch label has done its job:

$ git branch -d feature
Deleted branch feature (was 469aa30).

Deleting a merged branch loses nothing. Its commits are part of main's history now; only the sticky note goes. If the branch is not merged yet, git refuses, to protect you.

Practice

If the branches changed different files, or different parts of the same file, git combines them automatically. It stops and asks only when both sides changed the same lines. That is a merge conflict, and it is the next stop.

Keeping a long branch up to date

Working on a branch for a few days while main moves on? Merge main into your branch now and then, so the final merge is small:

$ git switch my-feature
$ git merge main

Same command, opposite direction: now main's new commits flow into your branch.

You want feature's changes in main, and you are currently on feature. What do you run?

Right. Merges go into the branch you are on. git merge main from feature would pull main into feature, which is the opposite direction (useful, just not what was asked).

When does a fast-forward happen?

Right. Nothing to combine, so git only moves the label. No merge commit.
