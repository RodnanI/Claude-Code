Git, from absolute zero

You keep hearing "just push it to GitHub" as if everyone was born knowing what that means. Nobody was. This guide assumes you know nothing: not what a terminal is, not what a commit is. By the last stop you will be branching, fixing merge conflicts and opening pull requests without breaking a sweat.

How this guide works

It is drawn like a metro map. Every chapter is a stop, and the stops are grouped into colored lines. Ride them in order the first time. Later, jump around with the route map on the left or the search box (Ctrl + K, or just /).

  • AFoundationsThe terminal, what git is, installing it.
  • BEveryday gitSaving snapshots, reading history, ignoring junk.
  • CBranchingParallel versions, merging them back, surviving conflicts.
  • DGitHubPushing, pulling, logging in, pull requests, forks and the website itself.
  • ERescue and habitsUndoing mistakes, handy tools, working like a professional.
  • FTerminusA final challenge, a sandbox, a cheat sheet and a glossary.

You cannot break anything here

Most stops have a practice terminal: a pretend command line running a simulated git, right inside this page. It never touches your real computer, so type whatever you like, make mistakes on purpose, and hit Reset when things get weird.

Practice terminals come with missions, short step-by-step goals that tick themselves off as you go. Stuck? Every step has a hint, and the buttons under each terminal type example commands for you (you still press Enter yourself, so you see what happens).

Words with a dotted underline, like repository or commit, show a short definition when you hover or tap them. They all live in the glossary too.

Why does git even exist?

Picture writing a school essay. You save it. Then you want to make big changes but keep the old version, so you "Save As" a copy. Then another. A week later your folder looks like the left side below. Click the button a few times.

Now picture five people editing the same files on different computers all week. That is the problem git solves. It remembers every version of every file, who changed what and why, and it lets several people work on the same project and combine their work safely.

What you will be able to do

  • Use the terminal without fear
  • Save your work as commits and travel back to any of them
  • Try ideas on branches without breaking the working version
  • Merge branches and calmly fix merge conflicts
  • Put a project on GitHub, then push and pull changes
  • Open, review and merge pull requests the way real teams do
  • Undo almost any mistake, and know which undos are dangerous

Reading everything and doing every mission takes a few hours. You do not have to do it in one sitting: the page remembers which stops you have visited. That memory stays in this browser; nothing is sent anywhere.

What is the main job of git?

Right. Git is a history recorder for a folder of files. Putting things online is what sites like GitHub add on top.
