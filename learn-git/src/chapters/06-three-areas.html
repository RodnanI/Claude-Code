The three areas (the big idea)

If git ever confuses you, it is almost always about this. Your changes live in one of three places, and nearly every everyday command just moves them between those places.

Where changes live

  1. Working directory The real files in your project folder, the ones you open and edit. Git notices changes but saves nothing automatically.
  2. Staging area (also called the index) A draft of your next commit. git add copies a change here. Stage one file, a few, or everything.
  3. Repository The permanent history inside .git. git commit takes whatever is staged and saves it as a new snapshot.

Think of a train station. Your working directory is the city, where passengers (your changes) wander around. The staging area is the platform: only the passengers you send there will board. git commit is the train leaving: everyone on the platform travels together, and the departure goes into the timetable forever. Passengers still in the city simply wait for a later train.

Why have a staging area at all?

Because you rarely change just one thing. Say you fixed a typo and also started on a new feature. You want two separate commits, "Fix typo" and "Add search", so either can be understood or undone on its own. Staging lets you put only the typo fix on the platform, commit it, then deal with the rest.

Click through it

Press Edit on a file to change it, Stage to move the change onto the platform, then write a message and Commit. The dark box at the bottom shows the actual git commands your clicks correspond to.

The life of a file

Every file is in one of these states. git status is just a report of which files are where.

The commands

CommandWhat it does
git add file.txtStage one file
git add .Stage every change in this folder and below: new, modified and deleted files
git add -pWalk through your changes chunk by chunk and choose which to stage
git restore --staged file.txtUnstage it. Your edit stays in the file.
git restore file.txtThrow your edit away and put back the last committed (or staged) version
git commit -am "..."Shortcut: stage all modified tracked files and commit. Brand-new files are not included.
git diffShow changes you have not staged yet
git diff --stagedShow what is staged, which is exactly what the next commit will contain

git restore file.txt overwrites your file with the last saved version. Edits you never committed are gone, with no undo. Not sure? Use git stash instead (see power tools).

Practice

You changed two files but want to commit only one of them. What do you do?

Right. Only staged changes go into a commit. The other file stays modified in your working directory, ready for a later commit.

git diff prints nothing, but git status lists "Changes to be committed". Why?

Right. Use git diff --staged to see staged changes. This confuses everyone at least once.
