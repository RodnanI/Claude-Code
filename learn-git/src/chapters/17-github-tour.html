The rest of GitHub

GitHub is more than a place to push. A quick tour of the features you will bump into: READMEs, issues, releases, Actions, Pages, and the settings that protect your main branch.

The repository page

Code
Files, the branch dropdown (top left), commit history (the clock icon), and the green Code button with the clone URL.
Issues
Bug reports, ideas and to-dos, each with its own discussion.
Pull requests
Open and past pull requests.
Actions
Automation runs, such as tests and deployments.
Settings
Collaborators, branch protection, Pages, secrets. Only visible with admin rights.

At the top: Star (a public bookmark, and a thank-you to the authors), Watch (notifications) and Fork.

Press . (the period key) on any repository page on github.com to open it in a full VS Code editor in your browser. Press t to search files by name.

README.md and Markdown

A file named README.md at the top of your repository is shown as the project's front page. The .md stands for Markdown: plain text with a few symbols for formatting. The same syntax works in issues, pull request descriptions and comments. Edit the left side:

You typeYou get
# Title, ## SectionHeadings
**bold**, *italic*bold, italic
- item or 1. itemA bulleted or numbered list
- [ ] taskA checkbox (clickable in issues and pull requests)
`code`Inline code
[text](https://...)A link
> quoteA quote block

A good README answers what the project is, how to install or run it, and how to contribute.

Issues

Issues are a project's to-do list and bug tracker. Each has a number (#12), a discussion, labels like bug or good first issue, and assignees. Mention one anywhere by typing #12. Write Closes #12 in a pull request description and the issue closes itself when the PR is merged.

A useful bug report says what you did, what you expected, what happened instead, and which versions you use. Screenshots help enormously.

Releases

A release is a named version of your project, like v1.2.0, with notes about what changed and files to download. It is built on a git tag. Create one from Releases, Draft a new release on the repository page; GitHub can even write the notes from your merged pull requests.

GitHub Actions: the green check

GitHub Actions runs scripts automatically when something happens. The classic example: run the tests on every push and pull request. That is where the green checkmark or red X on commits and PRs comes from, a practice called CI. A workflow is a small YAML file in .github/workflows/:

.github/workflows/test.yml
name: test
on: [push, pull_request]        # when to run
jobs:
  test:
    runs-on: ubuntu-latest      # a fresh virtual machine
    steps:
      - uses: actions/checkout@v4   # get the code
      - run: npm install            # install dependencies
      - run: npm test               # run the tests

You do not have to write these on day one. Just know what the checks on your pull request are, and click Details next to a red X to see what failed.

GitHub Pages: free website hosting

A repository of HTML files can be published as a website for free: Settings, Pages, pick the branch, and it appears at https://you.github.io/repository-name. Perfect for portfolios, documentation and small projects. A standalone HTML file like this guide would work there as-is.

Protecting main

Under Settings, Rules (or Branches), admins can protect main: require a pull request for every change, require approvals and passing checks, and block force pushes. That is why the Merge button in the pull request walkthrough stayed locked until someone approved.

Other things you will run into

LICENSE
States what others may legally do with your code. No license means nobody else may reuse it. choosealicense.com helps you pick.
.github/
Templates for issues and pull requests, workflows, and CODEOWNERS (who must review which files).
Gists
gist.github.com, for sharing a single snippet quickly. Each gist is secretly a tiny git repository.
Discussions
A forum tab for questions that are not bugs.
Security tab
Dependabot alerts about vulnerable libraries, with automatic pull requests that update them.
