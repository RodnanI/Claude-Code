Undo (almost) anything

Once something is committed, it is very hard to lose it for good. This stop is your emergency manual: pick your situation, get the exact commands, and know which undos are harmless and which are not.

The golden rule of undoing

A commit that exists only on your computer can be rewritten freely: amend it, reset it, rebase it. Once it is pushed and others may have it, do not rewrite it. Use git revert instead, which undoes it with a new commit.

reset: moving the branch backwards

Reset moves your current branch back to an earlier commit. The mode decides what happens to the changes from the commits you stepped back over. Try all three tabs and watch the areas panel:

ModeBranch moves backStaging areaYour files
--softYesChanges stay stagedUntouched
--mixed (default)YesUnstagedUntouched, the changes are still there
--hardYesClearedReset too. Uncommitted work is gone.

revert: undoing in public

Revert removes nothing. It creates a new commit that does the exact opposite of an old one. History stays intact, so it is safe on shared branches.

amend: fixing the last commit

A typo in the message, or a forgotten file? git commit --amend replaces the last commit with a corrected one. It is a new commit with a new hash, so only amend before pushing.

reflog: the safety net under the safety net

Git privately writes down every place HEAD has been, in the reflog. Reset too far? Deleted a branch? Botched a rebase? The commits are almost certainly still there, and the reflog tells you their hashes:

$ git reflog
44fd3dc (HEAD -> main) HEAD@{0}: reset: moving to HEAD~1
06314b3 HEAD@{1}: commit: Add taco recipe
44fd3dc HEAD@{2}: commit: Add salsa
$ git reset --hard HEAD@{1}
HEAD is now at 06314b3 Add taco recipe

Reflog entries are kept for about three months, and commits nothing points to survive at least a couple of weeks. The reflog is local: it only knows what happened on this computer.

Changes that were never committed. If you git restore a file, or git reset --hard or git clean away uncommitted edits, git never had a copy of them. That is the real reason to commit often: every commit is a save point you can always return to.

Practice: fix a messy repository

You pushed a bad commit to main, and your team already pulled it. How do you undo it?

Right. Revert adds a new commit that everyone can simply pull. Resetting and force pushing would rip the commit out from under your team.

Which reset mode can permanently destroy uncommitted changes?

Right. --hard overwrites your files. The other two only move the branch and the staging area.
