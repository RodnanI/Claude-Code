GitHub and remotes

So far everything lived on your computer. Now we connect it to GitHub, so your work is backed up online and other people can download it, add to it and send it back.

What a remote is

A remote is another copy of your repository somewhere else, usually on GitHub. It has its own commits and branches. Your git does not stay in constant contact with it. It only talks to the remote when you tell it to, using three commands:

push

Upload your new commits to the remote.

fetch

Download new commits from the remote, without touching your files or branches.

pull

Fetch, then merge what arrived into the branch you are on.

Step 1: an account and an empty repository

  1. Sign up at github.com. Your username becomes part of every repository URL, so pick one you will still like in five years.
  2. Click the + at the top right, then "New repository".
  3. Name it, for example recipes, and choose Public or Private.
  4. Leave "Add a README", .gitignore and license unticked if you are about to upload an existing project. Otherwise GitHub makes a first commit your project does not have, and your first push gets rejected.
  5. Click "Create repository". GitHub shows a page of setup commands including your repository's URL, like https://github.com/you/recipes.git.

Step 2: connect and push

$ git remote add origin https://github.com/you/recipes.git
$ git push -u origin main
git remote add
Save a remote under a short name.
origin
That name. origin is only a convention for "the main remote"; it could be called anything.
-u
Short for --set-upstream: remember that my local main belongs with origin's main. After doing this once, plain git push and git pull know where to go.
origin main
Where to push (origin) and which branch (main).

The first push asks you to log in, and your GitHub password will not work there. The next stop explains what to do instead.

GitHub's setup page also shows git branch -M main. It renames your current branch to main, for people whose git still starts on master. Harmless if you are already on main.

Or start from GitHub: git clone

If the project already exists on GitHub (yours or anybody's public project), download it with clone. Copy the URL from the green Code button on the repository page:

$ git clone https://github.com/you/recipes.git
Cloning into 'recipes'...
$ cd recipes

Cloning gets you every file, every commit and every branch, and sets up origin automatically. It creates a new folder, so do not forget the cd.

origin/main: your computer's memory of GitHub

After you fetch, pull or push, branches like origin/main show up in the log. These remote-tracking branches are read-only bookmarks meaning "where main was on GitHub last time we talked". They only move when you fetch, pull or push. That is why git status can say "Your branch is up to date with 'origin/main'" while GitHub actually has newer commits: git simply has not asked yet.

Step through what happens when a teammate pushes. Watch the dashed origin/main label on your side.

When your push is rejected

$ git push
To https://github.com/you/recipes.git
 ! [rejected]        main -> main (fetch first)
error: failed to push some refs to 'https://github.com/you/recipes.git'

Normal, and not a problem with your work. GitHub has commits you do not have, because someone pushed since you last pulled. Git refuses to overwrite them. The fix is always the same: git pull (resolving conflicts if any), then git push again.

Do not "fix" a rejected push with git push --force. That replaces GitHub's history with yours and deletes your teammate's commits.

Remote commands

git remote -v
List remotes with their URLs
git remote set-url origin URL
Point origin somewhere else, for example after renaming the repository
git push
Upload the current branch to its upstream
git push -u origin name
First push of a new branch
git fetch
Download without touching your work
git pull
Download and merge into the current branch
git branch -a
List local branches plus the origin/ bookmarks

What is the difference between fetch and pull?

Right. Fetch is the safe look-before-you-leap version. Pull is fetch plus merge.

Your push was rejected with "fetch first". What now?

Right. Bring their work in first, then yours can go on top.
