Reading history

A history is only useful if you can read it. Learn to list commits, open one up, compare versions, and step back in time to look around.

git log

$ git log
commit 7ccb74ce66d73f1a89766c7ef7a3c9810db31af2 (HEAD -> main)
Author: Ada Lovelace <ada@example.com>
Date:   Tue Sep 15 10:07:38 2026 +0000

    Add guacamole recipe

commit f4ee3e34ec6c1269719ea7c2d8c20b788caac512
Author: Sam <sam@example.com>
Date:   Tue Sep 15 09:21:52 2026 +0000

    Add salt to pancakes

Newest first. When the list is longer than your screen, git shows it in a scrollable viewer: arrow keys and space scroll, and q gets you out. (Everyone gets stuck in there once. Now you know.)

Most of the time you want the short version:

$ git log --oneline
7ccb74c (HEAD -> main) Add guacamole recipe
f4ee3e3 Add salt to pancakes
2a4cc3a Add salsa recipe
dc90184 Add pancake recipe
3f1b2c0 Start the recipe book

And to see every branch drawn as a graph: git log --oneline --graph --all. The practice terminals draw that graph for you as a metro map instead.

Hashes: every commit's ID

That jumble like 7ccb74ce66d7... is the commit's hash, a unique ID git calculates from the commit's contents, author, time and parent. Change anything and the hash changes, which is how git can tell history was not tampered with.

You never need all 40 characters. The first 7 are enough to point at a commit: git show 7ccb74c.

HEAD: you are here

HEAD is git's name for "the commit you are on right now". Usually it points at a branch (HEAD -> main in the log), and the branch points at its newest commit. In the graphs in this guide, HEAD is the black label and the spinning ring around a station.

You can count backwards from it:

HEAD
the current commit
HEAD~1
one commit before it (also written HEAD^)
HEAD~3
three commits back

Looking inside a commit

$ git show f4ee3e3

prints the commit's details plus a diff: exactly which lines changed. Diffs look scary but have a simple structure. Hover the parts:

diff --git a/pancakes.txt b/pancakes.txt index 3b18e51..6f8a38c 100644 --- a/pancakes.txt +++ b/pancakes.txt @@ -2,3 +2,4 @@ - 2 cups flour - 2 eggs - 1 cup milk + - 1 pinch of salt

Hover or tap each part of the diff.

Comparing versions with git diff

git diff
Changes in your files that are not staged yet
git diff --staged
Staged changes: exactly what your next commit will contain
git diff HEAD~2
Everything that changed since two commits ago
git diff main feature
The difference between two branches

Run git diff --staged right before every commit. It is the cheapest code review you will ever get: you will catch leftover debug lines and files you did not mean to include.

Time travel

You can move HEAD to an old commit and see the project exactly as it was then. Your files change to match that moment, and nothing is lost: the newer commits are still there.

This state is called detached HEAD: HEAD points at a commit instead of a branch. It sounds alarming but it is just sightseeing mode. Look around, then go back with git switch main. Want to keep working from that old point? Put a branch there: git switch -c idea-from-the-past.

Practice

Handy history commands

git log -p file.txt
Every change ever made to one file, with diffs
git log --author="Sam"
Only one person's commits
git log --grep="salsa"
Commits whose message mentions a word
git log -n 5
Only the five newest commits
git blame file.txt
Who last changed each line (see power tools)

What does HEAD~1 mean?

Right. ~1 means one step back from HEAD, ~2 two steps, and so on.

In a diff, what does a line starting with - mean?

Right. - removed, + added, a leading space means unchanged context.
