The terminal, without the panic

Git lives in the terminal: the dark window where movie hackers type very fast. It looks intimidating, but it is just a very literal way of talking to your computer. Ten minutes here makes everything after it easy.

What it is

Normally you control your computer by pointing and clicking: double-click a folder to open it, drag a file to the trash. The terminal does the same jobs with typed commands. You type a command, press Enter, the computer does it and prints a reply.

Clicking

Double-click "Documents".
Right-click, New Folder, type "recipes".

Typing

cd Documents
mkdir recipes

Why bother? Typing is exact, fast and repeatable, and git was built for it. Every git tutorial, error message and forum answer speaks in commands. Learn this language and all of that becomes readable.

Terminal, command line, console and shell get used interchangeably. Strictly speaking, the terminal is the window and the shell is the program inside it that understands your commands (bash, zsh, PowerShell). You can ignore the difference for now.

Opening one

Install git first (the Install and set up stop shows how). It comes with Git Bash, a terminal that understands the same commands as Mac and Linux. Open the Start menu, type Git Bash, and open it. Use Git Bash for everything in this guide.

Windows also has PowerShell and Command Prompt. Git works in them, but some basic commands differ (Command Prompt uses dir instead of ls, for example), which is confusing while you are learning.

Bonus: in VS Code, Terminal, New Terminal opens one inside your editor. Pick "Git Bash" from the small dropdown next to the plus button.

Press Cmd + Space, type Terminal, press Enter. That is it. It runs a shell called zsh, which understands every command in this guide.

Bonus: in VS Code, Terminal, New Terminal opens one inside your editor.

Press Ctrl + Alt + T on most distributions, or search your apps for Terminal. You are most likely running bash, which understands everything here.

Reading the prompt

When the terminal is ready for you, it shows a prompt. Here is a typical one. Hover or tap the colored parts.

you@laptop ~/projects (main) $

Hover or tap a part of the prompt.

Tutorials (this one included) write commands as $ git status. The $ only marks "this is a command". Type just git status.

Anatomy of a command

Every command follows the same grammar: a program name, sometimes a subcommand, then options and arguments, separated by spaces.

git commit -m "Fix typo in the menu"

Hover or tap a part of the command.

A few more so the pattern sticks: ls -a is a program and a flag. cd Documents is a program and an argument. git push -u origin main is a program, a subcommand, a flag and two arguments.

Folders and paths

Files live in a tree of folders, which the terminal calls directories. A path gives directions through that tree, with / between names: ~/projects/recipes/pancakes.txt means "in my home folder, then projects, then recipes, the file pancakes.txt".

SymbolMeans
~Your home folder, like /home/you or C:/Users/you
.The folder you are in right now
..The folder one level up (the parent)
/At the start of a path, the very top of the drive. In the middle, a separator between names.

A path starting with / or ~ is absolute and works from anywhere. Anything else is relative to your current directory: cd recipes only works if a recipes folder exists right where you are standing.

The commands you actually need

pwd
Print working directory: which folder am I in?
ls
List the files and folders here. ls -a also shows hidden ones, whose names start with a dot (like .git).
cd folder
Change directory: walk into a folder. cd .. goes up a level, cd ~ (or plain cd) goes home.
mkdir name
Make a new directory.
touch notes.txt
Create an empty file (Git Bash, macOS and Linux).
cat notes.txt
Print a file's contents on the screen.
echo "text"
Print some text. With > the text goes into a file instead: echo "hello" > notes.txt creates or overwrites notes.txt. >> adds to the end.
rm notes.txt
Delete a file. There is no recycle bin. rm -r folder deletes a folder and everything in it.
clear
Wipe the screen. Nothing is undone, it just clears the clutter. Ctrl + L does the same.

Keyboard tricks that save hours

  • Tab finishes names for you. Type cd Doc and press Tab. If several names fit, it shows the options. This works in the practice terminal too.
  • Up and Down bring back commands you already ran. No retyping.
  • Ctrl + C cancels whatever is running, or the line you are typing. In most terminals it does not copy.
  • Copy and paste: in Git Bash, right-click (or Ctrl + Insert and Shift + Insert). On macOS, the usual Cmd + C and Cmd + V. On Linux, Ctrl + Shift + C and Ctrl + Shift + V.
  • Names with spaces need quotes: cd "My Documents". Simpler: never put spaces in project names. Use dashes, like my-project.

Many commands print nothing at all when they succeed. If you get the prompt back without an error, it worked.

You are in ~/projects/recipes. Which command takes you to ~/projects?

Right. .. always means one level up. cd projects would look for a folder called projects inside recipes, and pwd only tells you where you are.

A tutorial says: $ git status. What do you type?

Right. The dollar sign is the prompt, printed by the terminal. You type what comes after it.
