Stash, tags and power tools

Smaller commands that make daily life easier: parking half-done work, marking releases, copying single commits, and finding out who changed a line and when.

git stash: park your work

You are halfway through something when an urgent fix comes in, and git will not let you switch branches with conflicting uncommitted changes. Stash puts them in a drawer and hands you a clean folder:

$ git stash
Saved working directory and index state WIP on main: 3a1f2c9 Raise coffee price
# ...switch branches, fix the urgent thing, come back...
$ git stash pop
git stash
Park all changes to tracked files
git stash -u
Also park brand-new, untracked files
git stash push -m "note"
Park with a description
git stash list
See what is in the drawer
git stash pop
Take the newest one out and apply it
git stash apply
Apply it, but keep a copy in the drawer
git stash drop
Throw the newest one away

Stashes are easy to forget about. If you will be away from the work for more than an hour, a quick commit on a branch ("wip: halfway through the menu") is often safer. You can tidy it up later.

Tags: naming a release

A tag is a permanent label on one commit, usually a version number. Unlike a branch, it never moves.

$ git tag v1.0.0
$ git tag -a v1.1.0 -m "Adds dark mode"
$ git push origin --tags

Tags are not pushed automatically, so remember the last line. -a makes an annotated tag with a message and an author, which is what releases should use.

Most projects use semantic versioning, MAJOR.MINOR.PATCH. Bump PATCH for bug fixes (1.0.1), MINOR for new features that break nothing (1.1.0), and MAJOR when you break compatibility (2.0.0).

cherry-pick: copy one commit

Need one specific commit from another branch, but not the rest? Cherry-pick copies just that commit onto your current branch.

blame: who wrote this line?

$ git blame menu.txt
a4c1e20 (You 2026-09-14  1) Menu
9f3b7d1 (Sam 2026-09-15  2) Coffee 3.20
a4c1e20 (You 2026-09-14  3) Tea 2.50

For every line: the commit that last changed it, who made it and when. Then git show 9f3b7d1 tells you why. Despite the name, blame is for understanding code, not for pointing fingers. GitHub has a Blame button on every file too.

bisect: finding the commit that broke it

Something worked last month and is broken now, with 200 commits in between. git bisect runs a binary search: it checks out the commit halfway, you say good or bad, it halves again. You find the culprit in about 8 steps instead of 200.

$ git bisect start
$ git bisect bad              # the current version is broken
$ git bisect good v1.0.0      # this old version worked
# git checks out a commit in the middle. Test it, then:
$ git bisect good             # or: git bisect bad
# ...repeat until git names the first bad commit...
$ git bisect reset            # back to where you started

Aliases: shorter commands

Tired of typing? Make your own shortcuts:

$ git config --global alias.st status
$ git config --global alias.lg "log --oneline --graph --all"
$ git st
$ git lg

Aliases work in the practice terminals too.
