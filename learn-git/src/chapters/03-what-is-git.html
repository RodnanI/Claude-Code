What git actually is

Git is a time machine for a folder. It takes snapshots of your files when you ask, keeps every one of them, and lets many people add their own snapshots to the same project without trampling each other.

Version control in one sentence

Version control means keeping track of every change to a set of files over time, so you can see who changed what, when and why, and return to any earlier state. Git is the version control system nearly everyone uses, from solo hobby projects to Linux, Windows and most of the software you touch every day. Linus Torvalds wrote it in 2005 to manage the Linux kernel, and it is free and open source.

Snapshots, not save files

When you tell git "remember this", it takes a snapshot of the whole project and files it away with a short description. That saved snapshot is called a commit. Green lines were added in that commit, red lines removed. You can see who made each change and the reason they gave. A git history gives you exactly that, for every file in the project.

No. Git is clever about storage: files that did not change between snapshots are not stored again, and everything is compressed. A project with thousands of commits usually has only a few megabytes of history.

Git and GitHub are different things

This trips up everyone. Git is a program on your computer, and it works entirely offline. GitHub is a website (owned by Microsoft) that stores copies of git projects online and adds teamwork features on top: pull requests, code review, issues, automation.

Git

  • A program you install
  • Works offline, on your computer
  • Tracks history, branches and merges
  • Free and open source

GitHub

  • A website, github.com
  • Stores copies of repositories online
  • Adds pull requests, issues, code review, automation
  • Alternatives: GitLab, Bitbucket, Codeberg

Git is your camera and photo album. GitHub is a shared online album where the whole team uploads photos, comments on them and decides which ones make the final cut.

A little vocabulary before we start

repository
A project folder that git tracks, usually shortened to "repo". Its history lives in a hidden folder called .git inside it.
commit
One saved snapshot, with a message.
branch
A separate line of commits, for working on something without disturbing the rest.
remote
A copy of the repository somewhere else, usually on GitHub.
push / pull
Upload your new commits to a remote, or download other people's.

Each gets its own stop later. No need to memorize anything now.

What git is not good at

  • Huge binary files like videos, Photoshop files or game assets. Git keeps every version of every file, so a 2 GB video edited ten times becomes 20 GB of history. Git LFS exists for that.
  • Live co-editing like Google Docs. Git combines work in deliberate steps, not keystroke by keystroke.
  • Backing up your whole computer. It is built for projects, not for your photo library.

You are on a plane with no internet. Can you still make commits?

Right. Commits are saved in the .git folder on your own disk. You only need the internet to push them to GitHub later.
