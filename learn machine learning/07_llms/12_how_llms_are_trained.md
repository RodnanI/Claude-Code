# How LLMs Are Trained at Scale

Your mini GPT and a frontier model run the same algorithm, and they differ in data, scale, engineering and post-training. You probably will not pretrain a frontier model, but you will often make decisions that depend on how models were made, such as which model to pick, why it behaves a certain way and whether fine-tuning can fix a problem.

## Stage 1: pretraining data

The model learns from what it reads. Pretraining corpora run to trillions of tokens drawn from filtered web crawls such as Common Crawl derivatives, public code repositories, books, scientific papers, encyclopedias, forums and math, and increasingly from synthetic data generated by other models, such as textbook-style explanations, problems with solutions and rewritten web text.

Raw web text is mostly junk, so the data pipeline is a large part of the work. The steps are:

1. Text extraction from HTML, PDFs and so on.
2. Language identification.
3. Deduplication, removing exact and near duplicates (MinHash and similar), since duplicates waste compute and increase memorization.
4. Quality filtering, using heuristics (length, symbol ratios, repetition) and classifiers trained to recognize educational or high-quality text.
5. Safety and privacy filtering, removing toxic content and personal information where possible.
6. Decontamination, removing benchmark test questions so evaluation stays honest.
7. Mixing, which sets the proportions of code, math and each language, often tuned with small proxy models.

The lesson applies in every ML job: at fixed compute, better data beats more data, and data work is where much of the real advantage lies.

## Stage 2: pretraining compute and engineering

Recall: training costs about `6 x parameters x tokens` FLOPs. Frontier runs use thousands to tens of thousands of GPUs for weeks or months.

The model and its optimizer state do not fit on one GPU, so the work is split:

| Parallelism | Splits | Idea |
|-------------|--------|------|
| data parallel | the batch | every GPU has a full copy, processes different examples, gradients are averaged |
| FSDP / ZeRO | parameters, gradients and optimizer state | each GPU stores a shard, gathers what it needs just in time |
| tensor parallel | individual matrix multiplies | one layer's matrices split across GPUs |
| pipeline parallel | layers | GPU 1 runs layers 1-10, GPU 2 runs 11-20, micro-batches flow through |
| expert parallel | MoE experts | different experts live on different GPUs |
| sequence / context parallel | the sequence | long sequences split across GPUs |

Big runs also use bf16 or fp8 mixed precision, checkpoint often because hardware fails daily at this scale, watch for loss spikes, and measure throughput as MFU (model FLOPs utilization, the share of the hardware's peak actually used, where 40-50% is considered good).

For the learning rate, runs use warmup then cosine decay (as in your mini GPT) or warmup-stable-decay, which holds the rate constant for most of training and decays it quickly at the end, often finishing with a short annealing phase on the highest-quality data.

Most pretraining runs see each token about once (one epoch). Repeating data a few times is fine; many repetitions start to hurt.

## Scaling laws

Kaplan et al. (2020) showed that loss falls as a smooth power law in model size, data and compute across many orders of magnitude, so the loss of a big run can be predicted from small runs. That predictability is why companies were willing to spend so much: the returns could be estimated in advance.

Chinchilla (Hoffmann et al., 2022) refined the recipe. For a fixed compute budget, the best loss comes from scaling parameters and tokens together, at roughly 20 training tokens per parameter, which meant many earlier models were too big and undertrained. Since then, models are often trained far beyond Chinchilla-optimal, at hundreds or thousands of tokens per parameter, because a smaller model trained longer is cheaper to serve to millions of users. Training is paid once and inference continues forever.

Some capabilities appear to emerge suddenly at scale. Part of this is real and part is an artifact of all-or-nothing metrics, since a smooth improvement looks like a jump when you count only fully correct answers.

## Stage 3: post-training (turning a base model into an assistant)

### Supervised fine-tuning (SFT)

SFT trains on examples of `(conversation so far, ideal assistant response)` formatted with the model's chat template. The loss is usually computed only on the assistant's tokens. There are thousands to millions of examples, written by people or generated and filtered. Quality matters more than quantity: the LIMA paper (2023) got a strong assistant from only 1,000 carefully curated examples. SFT mainly teaches format and style, because the knowledge came from pretraining.

### Preference tuning: RLHF and DPO

People are better at comparing two answers than at writing perfect ones, so the data is preferences of the form "for this prompt, response A is better than B".

RLHF, used for InstructGPT and early ChatGPT, trains a reward model to predict which response humans prefer, then optimizes the LLM with reinforcement learning (classically PPO) for high reward. A KL penalty keeps it close to the SFT model so it does not drift into gibberish that fools the reward model. DPO (direct preference optimization, 2023) reformulates the problem to train directly on preference pairs with a classification-style loss, so there is no separate reward model and no RL loop. It is simpler and widely used, along with many variants. RLAIF and Constitutional AI (Anthropic) use AI feedback guided by a written set of principles to generate preferences or critiques, reducing the reliance on human labeling.

### Reinforcement learning with verifiable rewards

For math, code, logic puzzles and other tasks where answers can be checked automatically (run the unit tests, compare the final number), the model generates attempts and gets rewarded for correct ones. Trained this way at scale, models learn to produce long **chains of thought**: planning, checking, backtracking. This created the "reasoning model" generation from late 2024 onward. GRPO (group relative policy optimization), popularized by DeepSeek, is one widely used algorithm: sample several answers per problem and reward each relative to the group's average.

### Safety training

This teaches the model to refuse genuinely harmful requests without refusing harmless ones, to resist manipulation and to be honest about uncertainty. It involves red teaming, where people and models attack the model on purpose, plus targeted training data and evaluation.

### Known side effects

Optimizing a proxy such as a reward model or a test suite invites reward hacking, where the model finds loopholes; a code model might special-case the tests instead of solving the problem. Optimizing for human approval can also teach sycophancy, meaning the model agrees with users and flatters them, which is a well-studied problem. Over-refusal and under-refusal have to be balanced continually.

## Distillation

Distillation trains a small student model to imitate a large teacher, either on the teacher's generated outputs or on its full probability distributions (logits), which carry more information than single answers. Many fast, cheap models are made this way. Some providers' terms of service prohibit using their outputs to train competing models.

## Why this matters at work

A base model continues text and an instruct model follows instructions, so do not prompt a base model like a chatbot. Fine-tuning (file 20) is a small version of post-training: it changes behavior and format well but is a poor way to add many new facts, and retrieval is better for that. Quirks such as verbosity, hedging, refusals and sycophancy often come from post-training choices, and prompting and fine-tuning can shift them. When a model scores well on benchmarks and is mediocre on your task, remember Goodhart's law, possible contamination, and that your task was probably not in anyone's training mix. Build your own evaluation (file 22).
