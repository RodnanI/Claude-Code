Final exam

Twelve questions from across the whole line. No pressure: every answer comes with an explanation, and the stop number to revisit if it did not stick.

1. Git versus GitHub: which statement is true?

  • GitHub is required to use Git
  • Git runs on your PC; GitHub hosts copies of repositories online
  • They are the same thing

Stop 1. Git works offline; GitHub is a website built around it.

2. Right after installing Git, PowerShell says "git is not recognized". First thing to try?

  • Reinstall Windows
  • Open a new terminal window
  • Run git as administrator

Stop 3. Terminals only see programs that existed when they started.

3. What does git add index.html do?

  • Uploads index.html to GitHub
  • Copies the current version of index.html into the staging area
  • Creates a new file

Stop 5. Staging decides what goes into the next commit.

4. git status lists a file in red under "Untracked files". Meaning?

  • Git sees the file but has never been told to track it
  • The file is corrupted
  • The file is ignored

Stop 5. git add it to start tracking.

5. You committed with a typo in the message and have not pushed. Fix?

  • git revert HEAD
  • git commit --amend -m "Correct message"
  • Delete the .git folder

Stop 8. Amend replaces the last commit; fine because nobody else has it yet.

6. A bad commit is already on GitHub and teammates pulled it. Fix?

  • git reset --hard and git push --force
  • git revert it, then push
  • Ask GitHub support

Stop 8. Never rewrite shared history; add an undoing commit.

7. Which command creates a branch and switches to it?

  • git branch -d name
  • git switch -c name
  • git merge name

Stop 9. git branch name only creates; -c creates and switches.

8. To get branch feature into main, you...

  • git switch feature, then git merge main
  • git switch main, then git merge feature
  • git push feature main

Stop 10. You merge into the branch you are on.

9. After fixing a conflicted file, how do you mark it resolved?

  • Save it
  • git add the file, then git commit
  • git merge --abort

Stop 10. git add marks it resolved; the commit finishes the merge.

10. Your push is rejected: "the remote contains work that you do not have locally". Next?

  • git push --force
  • git pull, then git push
  • Create a new repository

Stop 11. Someone pushed first; integrate their work, then push.

11. You want to contribute to a project you cannot push to. The workflow?

  • Email your files to the owner
  • Fork, clone your fork, branch, push to your fork, open a pull request
  • Clone the original and push with --force

Stops 12 and 13.

12. You added .env to .gitignore but Git still tracks it. Why, and the fix?

  • .gitignore needs a restart
  • It was already tracked; git rm --cached .env and commit
  • Rename it to .ENV

Stop 14. Ignore rules only apply to untracked files. (And if it held a real secret: change that secret.)

Where to go from here

  • Put something real on GitHub. Notes, a small website, dotfiles, a school project. Use a branch and a pull request even when working alone; it builds the habit.
  • Host a website for free. GitHub Pages publishes a repository of HTML files as a live site (repository Settings → Pages).
  • Make a first open source contribution. Search GitHub for the label good first issue.
  • Go deeper. The book "Pro Git" is free on git-scm.com/book, and GitHub Skills (skills.github.com) has short hands-on courses that run inside real repositories.
  • Use your editor's Git panel. Now that you know what staging, commits and branches are, VS Code's Source Control view will make total sense.

And when something goes wrong: git status, read it slowly, and remember that committed work is almost never truly lost.
