Your first repository and commit

Do it in the simulator first, where nothing can go wrong. Then do the exact same thing on your own PC.

In the simulator

A folder called my-site with two files is waiting. The steps sit above the terminal; Type it for me fills in the command if you are stuck (you still press Enter). Try commands that are not in the steps too: git status is always safe.

What each command did

git init: start tracking this folder

Initialized empty Git repository in C:/Users/you/my-site/.git/

Creates the hidden .git folder. Your files are untouched. The forward slashes in the path are normal: Git comes from the Linux world and prints paths that way. Run git init once per project, never inside a folder that is already a repository.

git status: what is going on?

The command you will type more than any other. Read it top to bottom: which branch you are on, what is staged (green), what is changed but not staged (red), and what is untracked (red). It even tells you which command to run next, in brackets. When in doubt, git status.

git add: put changes in the staging area

Silent when it works. git add index.html stages one file, git add . stages everything in the folder, git add *.css stages all CSS files.

"LF will be replaced by CRLF"

On Windows, git add sometimes prints a warning about LF and CRLF. It is harmless: Git is telling you it will convert invisible line-ending characters. Stop 16 explains, with a demo.

git commit -m "message": save the snapshot

[main (root-commit) 3f9a2c1] First version of my site
 2 files changed, 6 insertions(+)
 create mode 100644 index.html
 create mode 100644 style.css
  • main: the branch the commit went on.
  • root-commit: the very first commit of the repository; it has no parent.
  • 3f9a2c1: the start of the new commit's unique ID.
  • "insertions" and "deletions" count changed lines. "create mode 100644" is file permission trivia you can ignore.

git log: the history

commit 3f9a2c1e8b7d6a5f4e3d2c1b0a9f8e7d6c5b4a39 (HEAD -> main)
Author: Ada Lovelace <ada@example.com>
Date:   Sat Sep 26 14:03:12 2026 +0200

    First version of my site

Newest commit first. If the output is long, Git shows it one screen at a time with a : at the bottom. That is the pager: Space scrolls, q quits. The terminal is not frozen; it is waiting for you.

Now on your real PC

  1. Open a terminal (it starts in your home folder) and make a projects folder with a first project inside, then step into it: 
    mkdir projects\my-site
cd projects\my-site
  2. Create a file with Notepad. It asks whether to create a new file: click Yes, type anything, save with Ctrl + S, close Notepad. 
    notepad index.html
  3. Turn the folder into a repository and look around: 
    git init
git status
  4. Stage and commit: 
    git add .
git commit -m "First commit"
git log

Done: a real repository with a real commit. Change the file, then repeat git status, git add, git commit. That loop is most of everyday Git.

Where to keep projects

Use a plain folder like C:\Users\you\projects. Avoid the Desktop and Documents if OneDrive syncs them (it often does by default): OneDrive and Git fight over the .git folder. Stop 16 has the details.

Writing good commit messages

Future you will read these when something breaks. A good message is a short summary (roughly 50 characters) written as a command, saying what the commit does:

WeakBetter
changesAdd contact form to homepage
fixed stuffFix broken link in footer
asdfMake header text readable on phones
updated index.html and style.css and the logo andThree separate commits, one per change

Commit whenever you finish one small, complete step you could describe in one sentence. Many small commits beat one giant "did everything" commit.

You typed git log and the terminal shows a : at the bottom and ignores your commands. What now?

  • Close the window, it crashed
  • Press q to leave the pager
  • Press Ctrl + S

Long output opens in a pager. q quits and gives you the prompt back.

What order builds a commit?

  • git commit, then git add
  • edit files, git add, git commit
  • git init before every commit

Edit, stage what you want with git add, then save it with git commit. git init happens once per project.

Which commit message is best?

  • update
  • Fix typo in homepage heading
  • I changed some things in the files today because they were wrong

Short, specific, and phrased as what the commit does.
