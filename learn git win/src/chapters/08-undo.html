Undoing mistakes

Once something is committed, Git almost never truly loses it. The skill is not avoiding mistakes; it is picking the right undo for the mistake you made.

The one rule

Before pushing vs after pushing

Not pushed yet: the commits exist only on your PC, so you may rewrite them (amend, reset). Already pushed: other people may have them, so never rewrite. Add a new commit that undoes the old one (revert). Rewriting shared history is how teammates lose work.

The undo commands, explained

git restore file: throw away unstaged edits

Puts the file back to how it is in the staging area (which, if you did not stage anything, equals the last commit). The edits are gone for good. They do not go to the Recycle Bin, because Git never saved them.

git restore --staged file: unstage

The opposite of git add. The change leaves the staging area but stays in your file. Completely safe.

git commit --amend: fix the last commit

Replaces the last commit with a new one containing whatever is staged now, plus a new message if you give one. Perfect for typos and forgotten files. It creates a new commit ID, which is exactly why you must not amend commits you already pushed.

# forgot a file:
git add forgotten.css
git commit --amend --no-edit

git revert: undo a commit by adding its opposite

Looks at what a commit changed and creates a new commit that changes it back. History stays intact (both commits are visible), which makes it the safe choice for anything already on GitHub.

git reset: move the branch backwards

Moves your branch to an earlier commit, as if later commits never happened. It has three strengths:

Careful with --hard

git reset --hard is one of the very few Git commands that destroys work you cannot get back: uncommitted changes. Run git status first and read it. The commits it removes can still be rescued for a while with the reflog (Stop 15); uncommitted edits cannot.

Old commands you will see online

Git added git restore and git switch in 2019 because the older git checkout did too many unrelated jobs. Older tutorials use the old forms. They still work:

Old wayNew way
git checkout -- filegit restore file
git reset HEAD filegit restore --staged file
git checkout branchgit switch branch
git checkout -b branchgit switch -c branch

Habits that make undo easy

  • Commit often. Committed work is recoverable almost forever. Uncommitted work is one bad command from gone.
  • Read git status before anything destructive.
  • Before an experiment, make a branch (next stop). If it fails, delete the branch.

You pushed a commit that broke the site. Teammates have already pulled it. What do you do?

  • git reset --hard HEAD~1, then push
  • git revert the commit, then push
  • git commit --amend

Pushed history is shared. git revert adds a fixing commit instead of rewriting history under your teammates' feet.

You staged passwords.txt by accident. How do you unstage it but keep the file?

  • git restore passwords.txt
  • git restore --staged passwords.txt
  • git reset --hard

--staged only touches the staging area. Without it, git restore works on your file instead.

Which command can delete work that is gone for good?

  • git revert
  • git restore --staged
  • git reset --hard

It overwrites your files, and uncommitted changes were never saved anywhere.
