What Git and GitHub actually are

Git is a time machine for a folder. GitHub is a website where those time machines live online, so people can back them up, share them, and work on them together. Two different things with confusingly similar names.

The problem Git solves

Everybody has done this. You are working on something important and you do not want to lose a good version, so you make copies:

With Git you keep working in normal files. Whenever you reach a good point, you tell Git to take a snapshot of the whole folder. That snapshot is called a commit. Each commit records:

  • exactly what every file looked like at that moment,
  • a short message you write ("Rewrite intro"),
  • who made it and when,
  • a unique ID, so you can point at it later.

With that, Git can show you what changed between any two commits, bring back any old version, and let you try risky ideas on a separate line of work (a branch) without touching the version that works.

Think of it like

Save points in a video game. You save before the boss fight; if the fight goes badly, you reload. Commits are save points for your project, except you keep all of them forever, each with a label saying what happened.

What Git is not

  • Not a backup on its own. Git stores its history inside your project folder. If the disk dies, the history dies with it. The copy on GitHub is what protects you.
  • Not only for code. Websites, notes, recipes, config files, books written in plain text: anything made of text files works beautifully. Large binary files (videos, Photoshop files, Word documents) can be stored, but Git cannot show you what changed inside them.
  • Not GitHub. Git runs on your PC and works fully offline. Which brings us to...

You can use Git your whole life without GitHub. You cannot use GitHub meaningfully without Git. Learn Git first (Line 2), then GitHub (Line 3).

Four words you will hear constantly

Repository (repo)
A project folder that Git is tracking, plus all its history.
Commit
One saved snapshot, with a message.
Branch
A separate line of commits, so you can work on something without disturbing the main version.
Remote
A copy of the repository somewhere else, usually on GitHub.

Why learn the commands instead of clicking buttons?

VS Code, GitHub Desktop and other apps offer buttons for Git, and they are fine. But every one of those buttons runs the same commands you will learn here. Knowing the commands means the buttons make sense, every tutorial and forum answer makes sense (they are all written as commands), and when a button fails with a Git error message, you can read it. This guide teaches the commands and points out the buttons along the way.

Your laptop is stolen. You used Git on your project daily but never pushed to GitHub. What is left?

  • Everything, Git syncs automatically
  • Nothing: the history lived on the laptop
  • Only the latest version

Git keeps history inside the project folder on your disk. Only a push to GitHub (or another remote) creates a copy elsewhere.

Which one needs an internet connection to work?

  • Git
  • GitHub
  • Both

Git is a program on your PC and works fully offline. GitHub is a website.

What is a commit?

  • A file you upload to GitHub
  • A saved snapshot of the whole project, with a message
  • A promise to finish the project

A commit captures every tracked file at one moment, plus who, when, a message and a unique ID.
