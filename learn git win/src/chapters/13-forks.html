Forks: contributing to other people's projects

You cannot push to a repository you do not own. That would be chaos. Instead you make your own copy on GitHub, a fork, change that, and send a pull request back to the original. This is how all of open source works.

Three copies of one project

Step by step

  1. On the project's GitHub page, click Fork (top right), then Create fork. You now own you/cool-game.
  2. Clone your fork (not the original), then connect the original under the name upstream: 
    git clone https://github.com/you/cool-game.git
cd cool-game
git remote add upstream https://github.com/zoe/cool-game.git
  3. Make a branch, change things, commit, and push the branch to your fork: 
    git switch -c faster-enemies
# edit, then:
git add .
git commit -m "Make enemies faster"
git push -u origin faster-enemies
  4. On GitHub, your fork shows the Compare & pull request banner. The PR form now has four boxes: base repository (zoe/cool-game), base (main), head repository (you/cool-game) and compare (faster-enemies). Check them, describe your change, create the PR.
  5. Leave Allow edits by maintainers ticked. It lets the project owner push small fixes onto your branch instead of asking you.

Practise the fork workflow

Keeping your fork up to date

The original keeps moving while you work. Your fork does not follow automatically. Two ways to catch up:

On your fork's page, GitHub shows "This branch is N commits behind". Click Sync fork, then Update branch. Afterwards run git pull on your PC.

git switch main
git fetch upstream
git merge upstream/main
git push

Shortcut

The GitHub CLI forks, clones and sets up upstream in one go: gh repo fork zoe/cool-game --clone

Finding a first contribution

  • Look for issues labelled good first issue or help wanted.
  • Read the project's CONTRIBUTING.md and README first; many projects have rules about tests, formatting or commit messages.
  • For anything bigger than a typo, comment on the issue before you start, so nobody duplicates work.
  • Documentation fixes are real contributions and a great way to learn a project.

Why can you not just push to someone else's repository?

  • Git forbids pushing on Windows
  • You have no write permission there; only owners and invited collaborators do
  • You can, if you use --force

GitHub answers with "Permission denied" (403). That is why forks exist.

In a fork setup, what do origin and upstream usually point to?

  • origin is your fork, upstream is the original
  • origin is the original, upstream is your fork
  • Both point to your fork

You clone your fork (origin) and add the original yourself under the conventional name upstream.
