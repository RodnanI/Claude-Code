Welcome aboard

This guide takes you from "what even is Git?" to opening pull requests on GitHub, on a Windows 10 or Windows 11 PC. You need zero experience. Not with Git, not with programming, not even with the black window where people type commands.

How this guide is built

Git is easiest to picture as a transit map, so that is how the whole guide works. Every chapter is a stop. Stops are grouped into five lines, and the map on the left shows where you are. Ride them in order the first time; later, jump around.

Your progress is remembered in this browser. Press Mark this stop as done at the bottom of a stop (or just use the Next button, which marks it for you) and the station on the map fills in.

First: which Windows do you have?

A few instructions differ between Windows 10 and Windows 11: where menus are, what is preinstalled. Pick yours with the switch at the top of the sidebar and the guide only shows what applies to you. Not sure which one you have?

  1. Press Win + R (the Windows logo key and R at the same time). A small "Run" box appears.
  2. Type winver and press Enter.
  3. The window that opens says Windows 10 or Windows 11 in big letters. Set the switch to match.

What you need

  • A Windows 10 or 11 PC with internet access.
  • Permission to install programs. On a school or work PC that might mean asking IT.
  • A free GitHub account, but not yet. Stop 11 walks you through making one.

How to read this guide

Dark boxes like the one below are commands. You type them (or paste them) into the terminal and press Enter. Do not type the grey PS> at the start: that is the terminal's prompt, shown so you know where the command goes. Lines starting with # are comments, notes for you. The Copy button copies only the commands.

# This is a comment. The line below is a command.
git --version

Light boxes show what the terminal prints back:

git version 2.51.0.windows.1

Words with a dotted underline, like repository or commit, have a short definition. Hover over them, tap them, or tab to them with the keyboard. The full list lives in the Glossary stop.

Practise without fear

Many stops contain a simulator: a pretend terminal and a pretend project, running entirely inside this page. They understand real Git commands and answer the way real Git does, but nothing you type can touch your actual files. Break things on purpose there. That is what they are for.

You see this in a dark box: PS> git status. What do you type?

  • PS> git status
  • git status
  • status

PS> is the prompt: the terminal already shows it. You type only the command itself, then press Enter.

How do you find out whether your PC runs Windows 10 or 11?

  • Open Git and ask it
  • Look at the colour of the Start button
  • Press Win + R, type winver, press Enter

winver opens a small "About Windows" window with the exact version.
